# BL-36 «Рецепты» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** У изделия появляется рецепт (проценты от массы), задание получает его независимую копию с возможностью заменить ингредиент, а материал из рецепта нельзя удалить физически.

**Architecture:** Две новые сущности-строки (`ProductRecipeIngredient`, `ShiftTaskRecipeIngredient`) вместо `jsonb`: рецепт изделия — эталон, копия в задании — снапшот на момент создания/смены изделия. Проверки — статический `RecipeRules` (как `MaterialRules`), инвариант владения копией — методы `Product.SetRecipe` и `ShiftTask.ApplyRecipe/ReplaceIngredient`. Тип ингредиента не хранится — берётся из `Material.Type`.

**Tech Stack:** ASP.NET Core 9, EF Core 9 + Npgsql, PostgreSQL 16, xUnit + FluentAssertions, Vue 3 + Element Plus, Vitest + jsdom.

## Global Constraints

- Спека — единственный источник решений: `docs/superpowers/specs/2026-11-03-bl-36-recipes-design.md`. Не переобсуждать.
- В 100 % входят **только пластики**; краситель в сумму не входит; сумма ≠ 100 % — предупреждение, **не блокировка** сохранения.
- Не больше **8** строк рецепта; процент — от **0.01 до 100**, не больше **2** знаков после запятой; материал в рецепте не повторяется; непустой рецепт обязан содержать хотя бы один пластик; новая строка не может ссылаться на архивный материал (уже сохранённая — может).
- Рецепт изделия правит менеджер/админ; наладчик и наблюдатель — только чтение.
- Замена ингредиента — менеджер/админ, **любой статус задания** (включая `Completed`/`Closed`), только материал **того же типа** и **активный**.
- `RecipeEdited` не хранится: `RecipeIngredients.Any(i => i.MaterialId != i.OriginalMaterialId)`.
- Смена изделия перезаписывает копию рецептом нового изделия; подтверждение — **только фронт**, сервер перезаписывает молча.
- `DomainException` → HTTP 400 (`ExceptionHandling/DomainExceptionHandler`). Сообщения и комментарии — по-русски.
- Legacy-данных нет: никаких fallback-ов, `nullable`-ради-совместимости полей и заполнения старых заданий.
- Никаких новых NuGet/npm-пакетов.
- `master` защищён: только feature-ветка `feature/bl-36-recipes` и PR через `gh pr create`.
- VERSION в конце: `1.20.0` → `1.21.0`.

```csharp
using Wintime.Control.Core.Enums;
using Wintime.Control.Core.Exceptions;

namespace Wintime.Control.Core.Policies;

/// <summary>
/// Строка рецепта на входе проверки (BL-36). Тип — из <c>Material.Type</c>,
/// признак архива — из <c>Material.IsActive</c>.
/// </summary>
public sealed record RecipeRow(Guid MaterialId, MaterialType MaterialType, bool MaterialIsActive, decimal Percent);

/// <summary>
/// Правила рецепта изделия и его копии в задании (BL-36). Чистые функции, без БД.
/// Сумма пластиков ≠ 100 % — не ошибка: это предупреждение в UI (см. <see cref="IsSumOk"/>).
/// </summary>
public static class RecipeRules
{
    public const int MaxIngredients = 8;

    /// <summary>
    /// Проверить набор строк рецепта. <paramref name="existingMaterialIds"/> — материалы,
    /// которые уже были в рецепте: архивную строку с таким материалом сохранять можно,
    /// добавлять архивный материал — нет.
    /// </summary>
    public static void Validate(IReadOnlyList<RecipeRow> rows, ISet<Guid> existingMaterialIds)
    {
        if (rows.Count > MaxIngredients)
            throw new DomainException($"В рецепте не может быть больше {MaxIngredients} ингредиентов.");

        var seen = new HashSet<Guid>();
        var plasticSum = 0m;

        foreach (var row in rows)
        {
            if (row.Percent <= 0m || row.Percent > 100m || decimal.Round(row.Percent, 2) != row.Percent)
                throw new DomainException("Процент ингредиента — от 0,01 до 100, не больше двух знаков после запятой.");
            if (!seen.Add(row.MaterialId))
                throw new DomainException("Материал указан в рецепте дважды.");
            if (!row.MaterialIsActive && !existingMaterialIds.Contains(row.MaterialId))
                throw new DomainException("Архивный материал нельзя добавить в рецепт.");
            if (row.MaterialType == MaterialType.Plastic)
                plasticSum += row.Percent;
        }

        if (rows.Count > 0 && plasticSum == 0m)
            throw new DomainException("В рецепте должен быть хотя бы один пластик.");
    }

    /// <summary>Сумма процентов пластиков; краситель не учитывается.</summary>
    public static decimal PlasticSum(IEnumerable<RecipeRow> rows) =>
        rows.Where(r => r.MaterialType == MaterialType.Plastic).Sum(r => r.Percent);

    /// <summary>Пустой рецепт допустим; иначе сумма пластиков должна быть ровно 100 %.</summary>
    public static bool IsSumOk(IReadOnlyList<RecipeRow> rows) =>
        rows.Count == 0 || PlasticSum(rows) == 100m;
}
```

```csharp
        // BL-36: рецепт изделия — строки-проценты. Cascade нужен для физического удаления
        // изделия без ссылок (исключение мягкого удаления); материал из рецепта не удаляют.
        builder.Entity<ProductRecipeIngredient>(entity =>
        {
            entity.HasKey(e => e.Id);
            // BaseEntity присваивает Guid в конструкторе, поэтому без ValueGeneratedNever EF
            // считает строку, добавленную в коллекцию загруженного изделия, «изменённой» (UPDATE).
            entity.Property(e => e.Id).ValueGeneratedNever();
            entity.HasOne(e => e.Product).WithMany(p => p.RecipeIngredients)
                  .HasForeignKey(e => e.ProductId).OnDelete(DeleteBehavior.Cascade);
            entity.HasOne(e => e.Material).WithMany()
                  .HasForeignKey(e => e.MaterialId).OnDelete(DeleteBehavior.Restrict);
            entity.Property(e => e.Percent).HasColumnType("numeric(5,2)");
            entity.HasIndex(e => new { e.ProductId, e.MaterialId }).IsUnique();
            entity.ToTable("ProductRecipeIngredients");
        });
```

```csharp
    /// <summary>
    /// BL-36: заменить рецепт целиком. Порядок строк — порядок <paramref name="rows"/>.
    /// Строки согласуются по материалу (обновляем существующие, а не пересоздаём) —
    /// иначе уникальный индекс <c>(ProductId, MaterialId)</c> ловит конфликт на сохранении.
    /// <paramref name="existingMaterialIds"/> — материалы, уже бывшие в рецепте (архивную
    /// строку сохранить можно, добавить архивный материал — нельзя).
    /// </summary>
    public void SetRecipe(IReadOnlyList<RecipeRow> rows, ISet<Guid> existingMaterialIds)
    {
        RecipeRules.Validate(rows, existingMaterialIds);

        var keep = rows.Select(r => r.MaterialId).ToHashSet();
        RecipeIngredients.RemoveAll(i => !keep.Contains(i.MaterialId));

        for (var index = 0; index < rows.Count; index++)
        {
            var row = rows[index];
            var existing = RecipeIngredients.FirstOrDefault(i => i.MaterialId == row.MaterialId);
            if (existing == null)
            {
                RecipeIngredients.Add(new ProductRecipeIngredient
                {
                    MaterialId = row.MaterialId, Percent = row.Percent, SortOrder = index
                });
            }
            else
            {
                existing.Percent = row.Percent;
                existing.SortOrder = index;
            }
        }
    }
```

```csharp
    /// <summary>
    /// BL-36: заменить рецепт изделия целиком. Порядок массива = <c>SortOrder</c>;
    /// пустой массив очищает рецепт. Сумма пластиков ≠ 100 % — не ошибка (предупреждение в UI).
    /// Правка рецепта архивного изделия разрешена.
    /// </summary>
    [HttpPut("{id:guid}/products/{productId:guid}/recipe")]
    [Authorize(Roles = $"{Roles.Admin},{Roles.Manager}")]
    public async Task<ActionResult<ProductDto>> SetProductRecipe(
        Guid id, Guid productId, [FromBody] SetProductRecipeRequestDto request)
    {
        var pt = await _context.ProductTypes.Include(t => t.Products)
            .FirstOrDefaultAsync(t => t.Id == id);
        var product = pt?.Products.FirstOrDefault(p => p.Id == productId);
        if (pt == null || product == null)
            return NotFound();

        var ingredients = request.Ingredients ?? new List<RecipeIngredientInputDto>();
        var materialIds = ingredients.Select(i => i.MaterialId).ToList();
        var materials = materialIds.Count == 0
            ? new List<Material>()
            : await _context.Materials.Where(m => materialIds.Contains(m.Id)).ToListAsync();

        var rows = new List<RecipeRow>();
        foreach (var item in ingredients)
        {
            var material = materials.FirstOrDefault(m => m.Id == item.MaterialId);
            if (material == null)
                return NotFound("Материал не найден.");
            rows.Add(new RecipeRow(material.Id, material.Type, material.IsActive, item.Percent));
        }

        var existing = product.RecipeIngredients.Select(i => i.MaterialId).ToHashSet();
        product.SetRecipe(rows, existing);
        await _context.SaveChangesAsync();

        // Перечитываем с материалами: у новых строк навигация Material ещё не заполнена.
        var refreshed = await _context.ProductTypes.Include(t => t.Products)
            .ThenInclude(p => p.RecipeIngredients).ThenInclude(i => i.Material)
            .FirstAsync(t => t.Id == id);
        var saved = refreshed.Products.First(p => p.Id == productId);
        return Ok(ToDto(saved, await UsedProductIdsAsync(new[] { productId })));
    }
```

```csharp
    // ─────────────────────────────────────────────────────────────────────────
    // Рецепт задания (BL-36): копия рецепта изделия, сделанная при создании или
    // смене изделия. Строки не добавляются и не удаляются вручную, процент не
    // правится — только замена материала на материал того же типа, в любом статусе.
    // ─────────────────────────────────────────────────────────────────────────

    /// <summary>
    /// «Рецепт правился вручную» — хотя бы одна строка указывает не на исходный материал.
    /// Не хранится: замена туда и обратно правкой не считается.
    /// </summary>
    public bool RecipeEdited => RecipeIngredients.Any(i => i.MaterialId != i.OriginalMaterialId);

    /// <summary>
    /// BL-36: перезаписать копию рецептом изделия. Вызывается при создании задания
    /// и при реальной смене изделия; нет рецепта у изделия — копия пустая.
    /// Требует загруженной навигации <see cref="ProductRecipeIngredient.Material"/> —
    /// она же становится копией, поэтому И Include рецепта, и ThenInclude материала обязательны.
    /// </summary>
    public void ApplyRecipe(IEnumerable<ProductRecipeIngredient> productIngredients)
    {
        RecipeIngredients.Clear();
        var order = 0;
        foreach (var ingredient in productIngredients.OrderBy(i => i.SortOrder))
        {
            var material = ingredient.Material
                           ?? throw new InvalidOperationException("Материал рецепта изделия не загружен.");
            RecipeIngredients.Add(new ShiftTaskRecipeIngredient
            {
                MaterialId = material.Id,
                Material = material,
                OriginalMaterialId = material.Id,
                OriginalMaterial = material,
                Percent = ingredient.Percent,
                SortOrder = order++
            });
        }
    }

    /// <summary>
    /// BL-36: заменить материал строки копии. Только материал того же типа и активный;
    /// статус задания не проверяется — замена разрешена в любом статусе (даже после закрытия).
    /// Выбор исходного материала возвращает строку к исходному состоянию.
    /// Требует загруженной навигации <see cref="ShiftTaskRecipeIngredient.Material"/>.
    /// </summary>
    public void ReplaceIngredient(Guid ingredientId, Material newMaterial)
    {
        var row = RecipeIngredients.FirstOrDefault(i => i.Id == ingredientId)
                  ?? throw new DomainException("Строка рецепта не найдена.");
        var current = row.Material
                      ?? throw new InvalidOperationException("Материал строки рецепта не загружен.");

        if (!newMaterial.IsActive)
            throw new DomainException("Архивный материал нельзя выбрать ингредиентом рецепта.");
        if (newMaterial.Type != current.Type)
            throw new DomainException(
                $"Можно выбрать только {MaterialRules.TypeLabel(current.Type)} — как у текущего ингредиента.");

        row.MaterialId = newMaterial.Id;
        row.Material = newMaterial;
    }
```

```csharp
    /// <summary>
    /// BL-36: заменить материал ингредиента копии рецепта. Только активный материал того же типа;
    /// статус задания не проверяется — замена разрешена в любом статусе, включая завершённые.
    /// Выбор исходного материала возвращает строку к исходному (RecipeEdited сбрасывается).
    /// </summary>
    [HttpPut("{id:guid}/recipe/{ingredientId:guid}")]
    [Authorize(Roles = $"{Roles.Admin},{Roles.Manager}")]
    public async Task<ActionResult<TaskDto>> ReplaceRecipeIngredient(
        Guid id, Guid ingredientId, [FromBody] ReplaceRecipeIngredientRequestDto request)
    {
        var task = await _context.ShiftTasks
            .Include(t => t.Imm)
            .Include(t => t.Mold)
            .Include(t => t.Product).ThenInclude(p => p!.ProductType)
            .Include(t => t.Personnel)
            .Include(t => t.Order)
            .Include(t => t.RecipeIngredients).ThenInclude(i => i.Material)
            .Include(t => t.RecipeIngredients).ThenInclude(i => i.OriginalMaterial)
            .FirstOrDefaultAsync(t => t.Id == id);
        if (task == null)
            return NotFound();
        if (task.RecipeIngredients.All(i => i.Id != ingredientId))
            return NotFound();

        var material = await _context.Materials.FirstOrDefaultAsync(m => m.Id == request.MaterialId);
        if (material == null)
            return NotFound("Материал не найден.");

        task.ReplaceIngredient(ingredientId, material);
        await _context.SaveChangesAsync();

        var schedule = await _factoryClock.GetScheduleAsync();
        return Ok(task.ToDto(schedule));
    }
```

```js
// Рецепт (BL-36): проценты от массы изделия. В 100 % входят только пластики —
// краситель в сумму не входит. Сумма ≠ 100 % — предупреждение в UI, не запрет.
export function isPlastic(row) {
  return row?.materialType === 'Plastic'
}

export function plasticSum(rows) {
  return (rows ?? []).filter(isPlastic).reduce((sum, row) => sum + Number(row.percent ?? 0), 0)
}

// Округление до копеек процента: 33.33 + 33.33 + 33.34 не должно «не сходиться» из-за float.
export function isRecipeSumOk(rows) {
  const list = rows ?? []
  if (list.length === 0) return true
  return Math.round(plasticSum(list) * 100) / 100 === 100
}

export function formatPercent(value) {
  if (value === null || value === undefined || value === '') return ''
  return String(Math.round(Number(value) * 100) / 100)
}

export function formatRecipe(rows) {
  const list = rows ?? []
  if (list.length === 0) return ''
  return list
    .map(row => `${row.materialArticle || row.materialName || '—'} — ${formatPercent(row.percent)} %`)
    .join('; ')
}

export function recipeSumHint(rows) {
  return `Сумма пластиков: ${formatPercent(plasticSum(rows))} % (должно быть 100 %)`
}

export function materialTypeLabel(type) {
  if (type === 'Plastic') return 'Пластик'
  if (type === 'Colorant') return 'Краситель'
  return ''
}
```

```markdown
# ADR-0023. Технологические умолчания изделия и их копия в задании

- Status: Accepted
- Date: 2026-11-03
- Related: [ADR-0020](0020-product-types-and-products.md), [ADR-0002](0002-task-state-machine-in-entity.md)

## Контекст

Изделию нужны технологические умолчания: рецепт (состав сырья в процентах от массы),
позже — вес изделия и прочие параметры (PZP-24/PZP-23). Задание же должно лить по тем
значениям, которые действовали на момент его создания: правка справочника не должна
задним числом менять уже выданные задания и испортить аналитику и паспорт партии (BL-27).

Отдельная потребность производства: нужного пластика может не быть на складе, и менеджер
должен заменить ингредиент в конкретном задании, не трогая справочник изделия.

## Решение

1. **Изделие хранит умолчания, задание — их копию.** `Product.SetRecipe` — эталон;
   `ShiftTask.ApplyRecipe` копирует его при создании задания и при реальной смене изделия.
   Правка рецепта изделия существующие задания не меняет.
2. **Строки, а не `jsonb` и не версии рецепта.** Две таблицы: `ProductRecipeIngredients`
   и `ShiftTaskRecipeIngredients`. Строки дают внешние ключи на `Material` (материал нельзя
   удалить из-под рецепта), дешёвую выборку «где используется материал» и обычные миграции.
   Версии рецепта отвергнуты: истории рецепта сейчас никто не спрашивает, а копия в задании
   уже фиксирует факт.
3. **Тип ингредиента не хранится** — это `Material.Type`. Тип материала неизменен, замена
   разрешена только тем же типом, поэтому денормализация не нужна.
4. **«Рецепт правился вручную» вычисляется**, а не хранится: строка копии помнит
   `OriginalMaterialId`, признак — `MaterialId != OriginalMaterialId`. Замена туда и обратно
   правкой не считается — это верное отражение, а не компромисс.
5. **Проверка при смене изделия — только на фронте.** Сервер перезаписывает копию молча:
   правило «подтверди потерю правки» — про UX, а не про целостность данных.
6. **Сумма пластиков ≠ 100 % — предупреждение.** Технолог видит красный итог, но сохранить
   может: рецепт может быть неполным на момент ввода. В 100 % входят только пластики.

## Последствия

- Замена материала разрешена в **любом** статусе задания, включая `Completed`/`Closed`:
  исправление ошибки наладки не должно требовать правки справочника.
- Материал, на который ссылается рецепт или `OriginalMaterialId`, физически не удаляется —
  только в архив (`409` на `DELETE /api/materials/{id}`).
- Каждое новое умолчание изделия (вес, упаковка, допуски) добавляется по этому же принципу:
  колонка/строка у `Product` + копия в задании при создании.

## Отвергнутые альтернативы

- **Один `jsonb`-столбец рецепта.** Нет FK на материалы, нельзя ответить «где используется
  материал» без разбора всех документов, миграции состава — через код.
- **Версии рецепта с датой действия.** Дороже и не нужно: копия в задании уже несёт факт.
- **Хранить признак «правился» флагом.** Рассинхронизируется при возврате исходного материала.
```

```markdown
> Состав сырья изделия в процентах от массы; в задании — его копия на момент создания.

## Что это

Рецепт отвечает на вопрос «из чего льётся изделие и в каких долях». Доля — **процент от массы
изделия**: пластики в сумме должны давать 100 %, краситель (суперконцентрат) добавляется сверх

Рецепт есть у **изделия** (`Product`), а не у типа и не у пресс-формы: цвета и марки одного типа
могут отличаться составом.

Задание получает **копию** рецепта при создании. Копия живёт своей жизнью: менеджер может
заменить в ней материал (например, другого производителя, если нужного нет), не меняя справочник.
```

```markdown
Рецепт — состав сырья в процентах от массы изделия. Заводится он **у изделия**:
«Справочники → Типы изделий» → «Редактировать» → у нужного изделия кнопка «Рецепт».
В рецепте до 8 ингредиентов: пластики и, при необходимости, краситель. В 100 % входят только
пластики — если сумма не 100 %, под таблицей горит красная подсказка, но сохранить можно.

Задание при создании получает **копию** рецепта своего изделия — в карточке задания блок
«Рецепт». Правка рецепта изделия уже созданные задания не меняет.

Если нужного материала нет, менеджер нажимает «Заменить» у строки в карточке задания и выбирает
другой материал **того же типа**. Замена доступна в любом статусе задания, даже после закрытия;
заменённая строка показывает «было: …». Чтобы вернуть исходный материал, выберите его тем же
действием. Если копия правилась вручную, при смене изделия (только «Планируется» и без заказа)
система предупредит, что правка будет очищена.

Материал, который есть в рецепте, удалить нельзя — его можно только отправить в архив.
Наладчик видит рецепт задания, но менять не может.
```
