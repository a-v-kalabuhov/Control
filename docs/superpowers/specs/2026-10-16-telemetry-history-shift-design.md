# Мониторинг, режим «История»: сдвиг окна кнопками ◀ ▶

- **Дата:** 2026-10-16
- **Источник:** запрос пользователя (пилот ПЗП): чтобы немного сдвинуть видимое окно истории
  телеметрии, приходится заново выбирать обе границы периода.
- **Объём:** только фронт, страница «Мониторинг» (`TelemetryDashboardView.vue`). Бэкенд, схема, ADR — нет.

## Акторы и сценарии (use cases)

| Актор | Сценарий |
|---|---|
| Технолог / мастер / наладчик | Смотрит историю сигналов ТПА за период, хочет посмотреть «чуть раньше» или «чуть позже» — нажимает ◀ / ▶, окно сдвигается на треть, графики перерисовываются без «Показать». |
| То же | Идёт вправо до текущего момента: окно встаёт концом на «сейчас», дальше ▶ неактивна. |

## Поведение

- Кнопки **◀** слева от поля «Начало» и **▶** справа от поля «Конец»; только в режиме «История».
- Шаг = ⌊(конец − начало) / 3⌋ мс; длина окна сохраняется.
- Сдвигаются **текущие значения полей** (даже если их поправили и не нажали «Показать»).
- **▶ у края:** если новый конец > «сейчас» — окно `[сейчас − длина, сейчас]`; если конец уже ≥ «сейчас» —
  ▶ неактивна.
- **◀** без ограничения.
- Обе кнопки неактивны, если не задана любая из границ, конец ≤ начала или не выбран ТПА.
- После сдвига новые границы записываются в поля (формат `YYYY-MM-DDTHH:mm:ss`, локальное время, как
  у `el-date-picker` с `value-format`) и вызывается `loadHistory()` (её проверки — включая лимит 4 ч —
  остаются; сдвиг длину не меняет).
- **Устаревшие ответы:** при быстрых нажатиях ответы могут прийти не по порядку. `fetchWindow`
  применяет только ответ на последний запрос (счётчик запросов); сейчас она отбрасывает лишь ответы
  для другого ТПА.

## Реализация

- `src/utils/telemetryWindow.js` — чистая `shiftWindow(fromMs, toMs, direction, nowMs)` →
  `{ fromMs, toMs }` или `null` (сдвигать некуда / окно некорректно). `direction`: `-1` ◀, `1` ▶.
- `TelemetryDashboardView.vue`: кнопки, `canShiftBack`/`canShiftForward`, `shift(direction)`, счётчик
  запросов в `fetchWindow`.
- Руководство менеджера, §3.3 «Режим „История"».

## Тесты (Vitest)

- `shiftWindow`: треть окна влево/вправо; прижатие к «сейчас»; `null` при конце ≥ «сейчас» для ▶;
  `null` при некорректном окне.
- Страница: ◀ сдвигает поля и запрашивает API с новыми `from`/`to`; ▶ неактивна, когда конец в
  «сейчас»/будущем; при двух быстрых сдвигах показывается ответ на последний, даже если первый
  пришёл позже.

## Не входит

- Выбираемый шаг, горячие клавиши, сдвиг в режиме «Живые данные», изменение масштаба (zoom) кнопками.
