# Страница «Мониторинг» (телеметрия ТПА) — дизайн

Дата: 2026-10-14 · Статус: утверждён

## Проблема

Из карточки ТПА (`ImmDetailModal`) кнопка «Телеметрия» ведёт на страницу `imm/:id/telemetry`
(`TelemetryDashboardView`). На этой странице:

- не видно, телеметрию какого ТПА смотрим;
- нельзя вернуться в карточку ТПА;
- нет пункта меню — попасть на страницу можно только из карточки.

Кроме того, кнопку «Телеметрия» видит Observer, но эндпоинты телеметрии (`/api/imm/{id}/signals`,
`/api/imm/{id}/telemetry-dashboard`) разрешены только `ManagerOrAdmin`, поэтому Observer получает 403.

## Акторы и сценарии (use cases)

Актор — Manager или Admin.

1. **Мониторинг из меню.** Пользователь открывает пункт меню «Мониторинг». Страница открывается с пустым
   полем «ТПА», телеметрия не отображается. Пользователь выбирает ТПА — отображается телеметрия
   (по умолчанию — живые данные, первый сигнал), как сейчас.
2. **Переход из карточки.** На дашборде пользователь открывает карточку ТПА и нажимает «Телеметрия».
   Открывается страница мониторинга, в поле «ТПА» подставлен этот ТПА, видна кнопка «Назад».
3. **Возврат в карточку.** Пользователь нажимает «Назад» — открывается дашборд, и на нём автоматически
   открывается карточка ТПА, указанного в поле «ТПА».
4. **Смена ТПА после перехода из карточки.** Пользователь пришёл из карточки ТПА-1, сменил в поле ТПА-2
   и нажал «Назад» — открывается карточка ТПА-2.
5. **Обновление страницы / ссылка.** F5 на странице мониторинга сохраняет выбранный ТПА и кнопку «Назад».
   F5 на дашборде после закрытия карточки карточку повторно не открывает.

## Решение

Всё состояние навигации — в query-параметрах URL:
`/monitoring?imm=<immId>&from=card`.

Отвергнуто:
- **Pinia-store с «контекстом возврата»** — теряется при F5, ссылкой не поделиться.
- **`router.back()`** — дашборд не помнит открытую модалку; не учитывает смену ТПА в фильтре.

### 1. Маршрут и меню

- Новый маршрут `monitoring`, name `Monitoring`, `meta: { roles: ['Admin', 'Manager'], title: 'Мониторинг' }`,
  компонент — `views/telemetry/TelemetryDashboardView.vue`.
- Маршрут `imm/:id/telemetry` (`ImmTelemetry`) удаляется (legacy-ссылок нет).
- В `DefaultLayout` — пункт меню верхнего уровня «Мониторинг» сразу после «Дашборда»,
  виден при `canAccess(['Admin', 'Manager'])`, иконка из `@element-plus/icons-vue` (например, `TrendCharts`).

### 2. Страница мониторинга

Функционально идентична текущей странице телеметрии (режимы история/живые данные, период, частота
опроса, выбор и порядок сигналов). Изменения:

- **Поле «ТПА»** — первым в панели фильтров: `el-select`, одиночный выбор, `filterable`, `clearable`.
  Опции — действующие ТПА: `immApi.getList({ isActive: true })`, подпись — `name`.
  Если `query.imm` ссылается на ТПА, которого нет в списке (архивный), он подгружается через
  `immApi.getById` и добавляется в опции; при ошибке загрузки (404) — поле очищается с предупреждением.
- **Источник истины — `route.query.imm`.** Выбор в поле → `router.replace` с новым `imm`
  (прочие query-параметры, в т.ч. `from`, сохраняются); очистка поля → `imm` удаляется из query.
  Компонент реагирует на изменение `route.query.imm` через `watch` (а не читает `route.params.id`
  один раз при setup, как сейчас).
- **Поле пустое** → live-опрос остановлен, данные сигналов/циклов/сегментов очищены, вместо фильтра
  сигналов и графиков — `el-empty` «Выберите ТПА». Переключатели режима/периода остаются видимыми.
- **Смена ТПА** → остановить live-опрос; очистить данные и выбор/порядок сигналов; загрузить сигналы
  нового ТПА (`getSignals`), выбрать первый; режим, период live, частота опроса и даты истории
  сохраняются; в live — перезапуск опроса, в истории — `loadHistory`, если обе даты заданы.
  Ответы, пришедшие для предыдущего ТПА после смены, игнорируются (сверка id ТПА запроса с текущим).

### 3. Кнопка «Назад»

- Показывается, если `route.query.from === 'card'` и ТПА выбран.
- Расположена слева в начале панели фильтров (перед полем «ТПА»).
- Клик → `router.push({ name: 'Dashboard', query: { imm: <ТПА из поля> } })`.

### 4. Дашборд и карточка ТПА

- `DashboardView`: при монтировании и при изменении `route.query.imm` — если значение задано,
  `selectedImmId = imm`, `detailModalVisible = true`. При закрытии модалки — `router.replace`
  без `imm` в query.
- `ImmDetailModal.goToTelemetry` → `router.push({ name: 'Monitoring', query: { imm: props.immId, from: 'card' } })`.
- Кнопка «Телеметрия» в карточке показывается только Admin/Manager (Observer — нет доступа к API телеметрии).

### 5. Чистые функции (`utils/monitoringNav.js`)

Логика навигации выносится в чистые функции, чтобы покрыть тестами:

- `monitoringQueryWithImm(query, immId)` — новый query при выборе/очистке ТПА (сохраняет прочие ключи,
  при пустом `immId` удаляет `imm`).
- `showBackToCard(query)` — `true`, если `from === 'card'` и `imm` задан.
- `dashboardQueryWithoutImm(query)` — query дашборда после закрытия карточки.

## Тестирование

- Vitest: юнит-тесты функций из `utils/monitoringNav.js`.
- Ручная проверка сценариев 1–5 в браузере (dev-сервер + эмулятор).

## Вне рамок

- Выбор нескольких ТПА на одной странице.
- Сохранение фильтров сигналов/режима между визитами.
- Изменения backend.
