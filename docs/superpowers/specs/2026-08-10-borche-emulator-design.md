> [Тестер USR-Modbus (Подзадача 2)](2026-07-16-usr-modbus-tester-design.md),

## 1. Назначение

Коннектор USR-Modbus сейчас проверен только на оборудовании Borche. Эмулятор воспроизводит
Modbus-slave стороны ТПА Borche, чтобы:

1. проверять поведение самого коннектора (реконнект, детект простоя, автомат состояния) без
   доступа к реальному ТПА;
2. вручную тестировать Control в связке с коннектором — вести конкретные сценарии (наладка,
   выпуск партии, авария, обрыв связи) и наблюдать реакцию приложения (дашборд, задания, отчёты).

Для ручного тестирования достаточно 1–2 зарегистрированных в Control ТПА одновременно — список
эмулируемых машин **не запрашивается у Control**, а берётся из локальных config-файлов
коннектора (см. §5).

Старый `Wintime.Control.Emulator` (публичное демо) — другая система: он сам публикует MQTT по
своей модели датчиков и пресетов. Эмулятор Borche ничего не публикует напрямую — он лишь отдаёт
сырые Modbus-регистры, а MQTT публикует боевой коннектор поверх них, как и в реальной эксплуатации.
Общая идея с генерацией по времени переносится (см. §7), но формат и механизм — новые.

## 2. Акторы и сценарии (use cases)

**Актор:** инженер/разработчик, вручную тестирующий коннектор и Control, у него есть готовый
ноутбук с эмулятором, боевым коннектором и (опционально) локальным Control.

- **UC1 — нормальный выпуск партии (автомат).** Задание на N изделий. Наладка: несколько циклов
  в Manual без брака. Наладчик переключает ТПА в Auto — циклы идут без поломок и простоев до
  выполнения нормы, ТПА уходит в простой (Idle), наладчик подтверждает завершение задания в
  Control.
- **UC2 — нормальный выпуск партии (полуавтомат).** Как UC1, но паузы между циклами
  варьируются (в основном 10–20 с — оператор снимает деталь), плюс несколько заметно более
  длинных пауз, превышающих порог простоя коннектора (`StateMachine.SeriesGapMs` — имитация
  того, что оператор отошёл к другому ТПА и не успел вернуться).
- **UC3 — авария посреди партии.** ТПА штатно завершает текущий цикл литья (форма открывается
  нормально), но следующий цикл не начинается — пресс-форма остаётся открытой на длительную
  паузу (несколько порогов простоя), пока не вмешается наладчик и не запустит ТПА заново.
  **Важно:** коннектор не снимает с ТПА причину остановки — эмулируется только наблюдаемый факт
  (цикл завершён, следующий не стартует), без отдельного "кода аварии".
- **UC4 — обрыв связи.** Два варианта: короткий разрыв (короче порога простоя — не должен
  сбрасывать автомат состояния коннектора, состояние 4 → возврат в исходное) и длинный разрыв
  (длиннее порога — коннектор должен пройти полный сброс в Offline/Start). Это действие над
  самим TCP-соединением, а не над значениями регистров.

Список открыт — пресеты пишутся по мере появления новых use case'ов (не обязательно расширять
этот раздел на каждый новый пресет-файл, если он не меняет требований к формату/движку).

## 3. Инварианты и границы

- Эмулятор — **modbus-slave**, коннектор к нему подключается как к обычному ТПА (master).
  Эмулятор ничего не публикует в MQTT и не знает про Control API.
- Список эмулируемых ТПА **не запрашивается у Control** — берётся из локальных
  `connector.json`-файлов, разложенных по каталогу конфигов коннектора (тот же формат/каталог,
  что читает боевой коннектор через `AliasConfigLoader`).
- Эмулятор **биндит modbus-slave на `device.host:device.port` из самого `connector.json`**
  каждого alias. Практическое следствие: конфиги, подготовленные для эмуляции, должны
  указывать локальный адрес (`127.0.0.1` или `0.0.0.0`) и **разные порты для разных ТПА** —
  это ответственность того, кто готовит тестовый набор конфигов, эмулятор это не проверяет и не
  переопределяет.
- Эмулятор переиспользует `Wintime.Connector.UsrModbus.Core` для схемы конфига
  (`ConnectorConfig`, `DeviceConfig`, `RegisterDef`, `SignalRole`, `ModbusAccess`, `RawType`,
  `ConfigLoader`) — не дублирует и не придумывает свою схему.
- Не эмулирует ничего, что коннектор не читает: например, причину аварии (см. UC3) — только то,
  что реально приходит по ролям `MoldClosed`/`Injection`/`MoldOpened`/`InjectionPosition` и
  прочим `published`-регистрам конкретного конфига.

## 4. Архитектура и стек

- Новый проект **`Wintime.Connector.UsrModbus.Emulator`** в решении коннектора
  (`Sources/Connectors/Wintime.Connector.UsrModbus`), рядом с Тестером. Консольное приложение,
  `net9.0`.
- Ссылка на **`Wintime.Connector.UsrModbus.Core`** — конфиг и типы регистров без дублирования.

  `ModbusFactory.CreateSlaveNetwork` / `IModbusSlave` с `DefaultSlaveDataStore` (отдельные
  массивы для coils / discrete inputs / holding / input registers), TCP-listener на
  `device.host:device.port`.
- UI — **Spectre.Console** (тот же стек, что у Тестера) — консольный TUI с Live-таблицами и
  меню.
- Тесты — новый проект **`Wintime.Connector.UsrModbus.Emulator.Tests`** (xUnit).

## 5. Обнаружение эмулируемых ТПА

Запуск: `emulator --config-dir <path>` (тот же каталог, что у боевого коннектора). При старте:

1. сканирует `*.json` в каталоге (не рекурсивно — тот же плоский layout, что у
   `AliasConfigLoader`);
2. для каждого файла: alias = имя файла без расширения, конфиг грузится через
   `Core.ConfigLoader.LoadFromFile` (тот же валидирующий путь, что у боевого коннектора и
   Тестера — конфиг, который не проходит `ConnectorProfileValidator`, не эмулируется, ошибка
   выводится и файл пропускается, а не падает весь процесс);
3. на каждый успешно загруженный alias поднимается свой modbus-slave на
   `device.host:device.port` этого конфига.

Ограничение на 1–2 ТПА для ручного тестирования — не техническое, а по объёму: TUI показывает
список поднятых машин, оператор выбирает, с какой сейчас работать (см. §8). Технических
препятствий держать больше — нет.

## 6. Регистровая модель (общая для ручного режима и пресетов)

На каждый alias эмулятор строит из `RegisterDef[]` конфига локальный **register bank** —
изменяемое хранилище "текущее логическое значение" по имени регистра, зеркалируемое в
данные modbus-slave по правилам `Access`/`RawType`/`Scale`/`Offset`/`Invert` конфига (обратное
преобразование к тому, что делает `Core` при чтении):

- дискретный регистр (`Coil`/`DiscreteInput`): логическое `bool` → сырой бит с учётом `Invert`
  (тот же флаг, что у коннектора, но применённый в обратную сторону — при `Invert=true`
  физический уровень пишется инвертированным, чтобы после чтения коннектором с тем же `Invert`
  получилось верное логическое значение). Физически дискретный сигнал переключается скачком —
  других правил изменения для него нет;
- аналоговый регистр (`InputRegister`/`HoldingRegister`, `RawType.UInt16`/`Int16`): логическое
  значение в физических единицах (`Unit` конфига — мВ, мм) → `raw = round((value − Offset) /
  Scale)`. Физически аналоговый сигнал (положение шнека/плиты и т.п.) не может измениться
  скачком — движок должен уметь **менять его непрерывно во времени**, а не только мгновенно
  выставлять (см. `RAMP` в §7.2).

Два способа записи в регистр (см. §7):

- `SET <RegisterName> <value>` — мгновенный скачок. Единственный допустимый способ для
  дискретных регистров; для аналоговых — обрывает любую текущую интерполяцию и сразу
  переставляет значение (жёсткий сброс, используется редко — например, начальное состояние).
- `RAMP <RegisterName> <target_value> <duration_ms>` — только для аналоговых регистров. Линейная
  интерполяция от **текущего** значения регистра к `target_value` за `duration_ms`. Это
  единственное правило изменения аналогового сигнала — намеренно без кривых/сплайнов/ease-in-out
  (та же дисциплина, что и с языком пресетов в §7.3 — не плодить лишние степени свободы).

Оба способа работают в **логических** единицах конфига (то же, что видит коннектор после
декодирования), а не в сырых Modbus-словах. Это верно и для ручного UI (§8: бегунок задаёт
`RAMP` до целевой позиции за короткое фиксированное время, переключатель — `SET`), и для
пресетов (§7) — обе части эмулятора работают через один и тот же register bank конкретного
alias, что даёт согласованность между live-табло и воспроизведением пресета.

**Реализация интерполяции.** Активный `RAMP` хранится как `(start_value, target_value,
start_time, duration_ms)`; сырое значение в хранилище modbus-slave пересчитывается фоновым
тиком с периодом заметно короче `device.pollIntervalMs` конкретного alias (по умолчанию
`min(50 мс, pollIntervalMs / 5)`) — иначе коннектор увидит не плавное изменение, а те же
дискретные скачки, только чаще. По истечении `duration_ms` значение фиксируется на
`target_value`, ramp снимается. Новый `RAMP`/`SET` до истечения текущего — обрывает его и
стартует новый от значения на момент обрыва (не от исходного `start_value`).

## 7. Пресеты — движок и формат

### 7.1 Общая модель

Ручное управление и пресет — один и тот же примитив: «выставить регистр X в значение Y (в момент
T)». Единый движок событий:

- **ручной режим** — событие применяется немедленно, инициатор — оператор в TUI;
- **пресет** — тот же тип события, с задержкой от старта воспроизведения, инициатор — плеер
  (play/pause/seek), читающий текстовый файл.

Запись сессии ручного управления в пресет (генерация `.preset`-файла из выполненных вручную
действий) в первую версию не входит — единый примитив событий это не исключает, добавить можно
будет позже без изменения формата, если понадобится.

### 7.2 Формат пресета — текстовый, построчный

Пресет — текстовый файл с расширением **`.preset`**, одна инструкция на строку, `#` —
комментарий. Время — миллисекунды от начала воспроизведения **этого файла** (для главного
пресета — от старта прогона; внутри макроса — от начала макроса, см. §7.3, у макроса отдельное
расширение `.mac`, пресет и макрос не взаимозаменяемы).

```text
# UC1 — наладка, потом автоматический выпуск партии
# наладка — 3 цикла без брака
AT +0       REPEAT CYCLE_NORMAL FROM "macros/cycle_normal" x3
# переключение в auto, выпуск оставшихся 495 деталей
AT +2000    REPEAT CYCLE_NORMAL x492
```

Базовые инструкции — все начинаются с `AT <t_ms|+delta>` (абсолютный или относительный от
предыдущей инструкции/блока момент), исключений нет:

- `AT ... SET <RegisterName> <value>` — установить логическое значение регистра (§6).
- `AT ... DISCONNECT <duration_ms>` — эмулятор закрывает TCP-слушатель (или разрывает активное
  соединение) для текущего alias на заданное время, затем поднимает снова с теми же значениями
  регистров, как будто ничего не произошло (UC4).
- `AT ... REPEAT <macro> [FROM "<path>"] x<N>` — прогоняет макрос `N` раз подряд; `AT` здесь
  задаёт момент начала всего блока (блок сам не мгновенный — занимает время, равное сумме
  длительностей `N` итераций), а не отдельной инструкции внутри него. `AT +0` — блок стартует
  сразу по завершении предыдущей инструкции/блока.

**Одновременность и `REPEAT`.** Пресет — строго линейная, одноголосая таймлиния: несколько
инструкций с одинаковым `AT` применяются к register bank атомарно, одним пакетом, **в порядке
следования в файле**, до того как этот alias отдаст следующий опрос — коннектор никогда не
увидит промежуточное состояние между `SET`/`DISCONNECT` внутри одной такой группы. Правило
работает только для мгновенных инструкций (`SET`/`DISCONNECT`). `REPEAT` в такой группе
участвовать не может — он не мгновенный (сам разворачивается во времени внутри своей
длительности), поэтому делить `AT` с чем-либо ещё для него не определено: `REPEAT` обязан быть
единственной инструкцией на своей отметке `AT`, иначе это ошибка парсера.

Фазы сценария (наладка/автомат/простой и т.п.) в формате никак не обозначаются отдельной
инструкцией — у Borche нет физического сигнала "режим", коннектор определяет его сам по факту
переходов циклов, поэтому обозначать фазу как исполняемую команду нечем и незачем. Границы фаз
внутри пресета документируются обычным `#`-комментарием.

### 7.3 Макросы

Макрос — переиспользуемый именованный блок инструкций с **относительным** временем от начала
своего исполнения. Хранится в отдельном текстовом файле того же формата (§7.2, обычно без
`DISCONNECT`), но с собственным расширением — **`.mac`**. Расширение обязательно и единственно
допустимое: файл с любым другим расширением не распознаётся движком как макрос — это, в
частности, явно отделяет макросы от пресетов (у тех своё расширение, `.preset`, см. §7.2): они
не взаимозаменяемы, пресет нельзя подключить через `REPEAT ... FROM`, только `.mac`.

- `REPEAT <macro> FROM "<relative/path>" x<N>` — первое упоминание макроса в пресете:
  подключает файл и сразу же прогоняет его `N` раз подряд, разворачивая абсолютное время по
  накоплению длительности предыдущих итераций. `<relative/path>` — путь **без расширения**
  (например, `"macros/cycle_normal"`) — движок сам подставляет `.mac`.
- `REPEAT <macro> x<N>` — повторное упоминание того же макроса дальше по пресету (после первого
  `FROM`) — не указывает путь заново.
- **Ограничение (осознанное, чтобы не скатиться в самодельный BASIC):** макросы **не могут
  ссылаться на другие макрос-файлы** — только пресет ссылается на макрос-файлы, один уровень
  вложенности. Внутри макроса нет условий, арифметических выражений и пользовательских
  переменных.
- **Единственная подстановка** — предопределённый счётчик итерации `{n}` (номер текущего
  повторения макроса, с 1), без выражений над ним (не `{n*2}`). Годится, например, для
  инкрементального `SET PartCounter {n}`, если такой регистр есть в конфиге.
- **Единственный источник вариативности времени** — `rand(min_ms, max_ms)` в позиции задержки
  инструкции (не в `value`) — закрывает UC2 (паузы 10–20 с). Не выражение общего вида, а ровно
  одна встроенная функция с двумя аргументами. Допустима **только** как аргумент `AT` (позиция
  `t_ms`/`+delta`) — ни в `SET`/`RAMP` value, ни где-либо ещё. Пересчитывается заново на
  **каждой** итерации `REPEAT` — макрос с `rand()` внутри, вызванный `x495`, даёт 495
  независимо разыгранных значений задержки, а не одно и то же число, зафиксированное при первом
  разворачивании.
- Особые/редкие события внутри длинной серии (длинная пауза в UC2, авария в UC3) задаются не
  вероятностью, а явными точками — отдельными `REPEAT <macro> x1` с другим макросом, вставленными
  в нужном месте последовательности вызовов в основном пресете (детерминированно, воспроизводимо
  между прогонами).
- **Переиспользование между пресетами предупреждает о побочном эффекте:** правка `.mac`-файла
  макроса молча меняет поведение во всех пресетах, которые на него ссылаются. Это ожидаемое
  поведение (обновили "эталонный нормальный цикл" — обновились все сценарии), не баг.

### 7.4 Опорный формат нормального цикла

Дефолтный `cycle_normal.mac` воспроизводит ту же логическую последовательность фронтов, что
уже используется как эталон поведения автомата в тестах Core (`MachineSim.RunNormalCycle`), но
с **физически правдоподобной** динамикой шнека — дискретные фронты остаются мгновенными
(`SET`), а движение шнека — линейная интерполяция (`RAMP`, §6), а не ступеньки:

```text
AT 0     SET MoldClosed 1
AT 0     SET Injection 0
AT 200   SET MoldClosed 0
AT 200   SET Injection 1
AT 200   RAMP InjectionPosition 5.0 400     # впрыск: плавно к подушке за 400 мс
AT 600   RAMP InjectionPosition 27.5 200    # набор дозы: плавно обратно за 200 мс
AT 800   SET Injection 0
AT 1000  SET MoldOpened 1
AT 1000  SET MoldOpened 0
```

Это референсный макрос "из коробки"; для UC2/UC3 нужны производные —
`cycle_normal_short_pause.mac` (доля секунд короче), `long_pause.mac` (только пауза, без
цикла), `alarm_stop.mac` (цикл завершается нормально, дальше долгая пауза — UC3).

## 8. Ручной TUI-режим

Консольный TUI на Spectre.Console (стек Тестера). Пункты меню:

1. **Выбор ТПА** — список alias'ов, поднятых из `--config-dir` (см. §5).
2. **Live-табло сигналов** — таблица по всем `RegisterDef` выбранного alias с ролью и текущим
   логическим значением; обновляется на каждое изменение через register bank:
   - дискретные (роли `MoldClosed`/`Injection`/`MoldOpened`, `Published`-регистры без роли,
     если они дискретные) — переключатель (on/off, `Enter`/пробел);
   - аналоговые (`InjectionPosition`, прочие `Published` аналоговые) — бегунок в диапазоне,
     заданном для конкретного регистра (для 0–10 В сигналов — 0–10, для остальных — по `Unit`
     конфига); диапазон берётся из отдельного файла настроек эмулятора, не из `connector.json`
     (см. §11 — решено, не расширять схему `Core` ради инструмента).
3. **Воспроизведение пресета** — выбор `.preset`-файла, play/pause/seek, индикатор текущей
   позиции и активного макроса/итерации.
4. **Разрыв связи** — ручной аналог `DISCONNECT` из TUI (для быстрой проверки UC4 без пресета).
5. **Выход.**

**Ограничение первой версии.** Modbus-slave для всех alias'ов из `--config-dir` поднимаются
параллельно и независимо (§5) — фоновая эмуляция многомашинная сразу. Но пресет/ручное
управление (пункты 2–4) — **единое активное состояние на всю TUI-сессию**, привязанное к
alias, выбранному в пункте 1: воспроизведение идёт только на нём, для работы со вторым alias
текущее действие нужно сначала остановить и переключиться. Параллельная интерактивная работа с
двумя ТПА одновременно (два независимых пресета в фоне сразу) в первую версию не входит — при
необходимости выносится отдельным пунктом позже.

## 9. Тестируемость (xUnit)

Без реального TCP и консоли:

- преобразование логическое ↔ сырое (`Scale`/`Offset`/`Invert`) для всех комбинаций
  `Access`/`RawType` — таблицы round-trip с `Core.ConfigLoader`/декодерами;
- линейная интерполяция `RAMP`: значение в произвольный момент внутри интервала, в момент 0 и в
  момент `duration_ms`, обрыв текущего ramp новым `SET`/`RAMP` до истечения (продолжение от
  значения на момент обрыва, не от исходного `start_value`), отказ парсера, если `RAMP` указан
  для дискретного регистра;
- парсер формата пресета/макроса: `AT`/`SET`/`RAMP`/`DISCONNECT`/`REPEAT ... FROM ... x N`,
  включая относительное время, накопление длительности при повторах, подстановку `{n}`,
  `rand(min,max)` (с фиксированным seed в тестах — детерминированно);
- ограничение "макрос не ссылается на макрос" — парсер должен явно отклонять такую ссылку с
  понятной ошибкой;
- расширение `.mac` у макросов: `REPEAT ... FROM "<path>"` без расширения в пути корректно
  резолвится в `<path>.mac`; файл с любым другим расширением по этому пути не подхватывается
  (понятная ошибка "макрос не найден", а не тихая загрузка не того файла);
- плеер: по заданному пресету — последовательность событий `(t_ms, register, value)` в
  правильном порядке и с правильным абсолютным временем (без реального ожидания — тест крутит
  виртуальные часы, как `MachineSim` в Core.Tests).

Modbus-slave (NModbus TCP listener) и Spectre-рендер — тонкие адаптеры, юнит-тестами не
покрываются; интеграционная проверка — прогон конкретных пресетов через боевой коннектор
вручную (то, ради чего эмулятор и делается).

## 10. Границы (не входит)

- Публикация MQTT, логика автомата состояния — целиком в боевом коннекторе; эмулятор не знает
  про Control API и MQTT-контракт.
- Причины аварий/остановок ТПА — не эмулируются как отдельный сигнал (см. UC3, §3) — коннектор
  их и не читает.
- Полноценный язык сценариев (условия, произвольные выражения, пользовательские переменные) —
  осознанно не делаем (см. §7.3); при потребности в более сложном сценарии — несколько
  пресет-файлов и явные точки вставки вместо логики внутри формата.
- Автоматическое согласование `device.host/port` между боевым и тестовым `connector.json` —
  ответственность того, кто готовит тестовый набор конфигов (§3).

## 11. Открытые вопросы

- ~~Диапазоны бегунков для конкретных аналоговых ролей/`Published`-регистров в TUI — где
  хранить~~ — **решено:** один файл настроек эмулятора на весь `--config-dir` (не
  `connector.json` — не расширяем схему `Core` ради инструмента), структура — по alias, внутри
  по имени регистра:

  ```yaml
  cnc-01:
    InjectionPosition:
      min: 0
      max: 60
    MoldPosition:
      min: 0
      max: 10
  cnc-02:
    InjectionPosition:
      min: 0
      max: 45
  ```

  Регистр, для которого нет записи в файле (или сам alias отсутствует), получает диапазон по
  умолчанию из `Unit` конфига (0–10 для мВ-сигналов и т.п., см. §8) — файл настроек не
  обязателен целиком, можно переопределить только нужные регистры. Точное имя файла (например,
  `emulator-ui.yaml`) — уточнить при реализации.
- ~~Нужен ли предпросмотр итогового расписания пресета (развёрнутый список `(t_ms, register,
  value)` до запуска) для отладки самого пресета~~ — **решено: не нужен.** Пресет и макросы —
  обычные текстовые файлы, отлаживаются во внешнем редакторе, не в самом эмуляторе; дублировать
  это как отдельную фичу TUI не требуется.
- ~~Формат хранения границ короткой/длинной паузы конкретно под тестовый `SeriesGapMs`~~ —
  **решено: ничего не делаем.** Величины пауз — обычные числовые константы в макросе/пресете,
  без символической привязки к порогу конфига (никакого `seriesGapMs` как встроенной
  переменной — не расширяем формат ради этого). Согласованность пауз в пресете с реальным
  `SeriesGapMs` конкретного тестового `connector.json` — ответственность инженера, готовящего
  тест: проверить перед прогоном, что заложенные в пресете паузы всё ещё короче/длиннее порога,
  как задумано сценарием.
