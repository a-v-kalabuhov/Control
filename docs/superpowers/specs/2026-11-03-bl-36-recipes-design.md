# BL-36 «Рецепты» — дизайн

Дата: 2026-11-03 · Блок В фидбека ПЗП (PZP-22 → **BL-36** → PZP-24 → PZP-23) · Зависит от PZP-22 (материалы)

## Цель

У изделия есть рецепт — состав сырья в процентах от массы изделия. Задание при создании получает
**копию** рецепта своего изделия; менеджер может заменить в копии материал на другой того же типа
(нет нужного пластика на складе), не трогая справочник. Наладчик видит рецепт задания только для чтения.

Принцип блока В: **изделие хранит технологические умолчания, задание — их копию** (ADR-0023).

## Акторы и сценарии (use cases)

| Актор | Сценарий |
|---|---|
| Менеджер / админ | **UC-1.** В диалоге типа изделия открывает «Рецепт» изделия, добавляет ингредиенты (материал + %), сохраняет. Если сумма пластиков ≠ 100 % — видит красное предупреждение, но сохраняет. |
| Менеджер / админ | **UC-2.** Правит рецепт изделия (добавить/убрать строку, сменить материал или %). Существующие задания не меняются. |
| Менеджер / админ | **UC-3.** Создаёт задание: копия рецепта заполняется из изделия автоматически; рецепт изделия виден в форме только для чтения. |
| Менеджер / админ | **UC-4.** В карточке задания заменяет материал ингредиента на другой активный материал того же типа — в любом статусе, даже после завершения. Видит «было: …». Может вернуть исходный материал тем же действием. |
| Менеджер / админ | **UC-5.** Меняет изделие в задании «Планируется» без заказа. Если копия рецепта правилась вручную — диалог «Рецепт в задании был изменён. При смене изделия изменения будут очищены. Хотите выбрать новое изделие?» (Да/Нет). «Да» — копия перезаписывается рецептом нового изделия при сохранении. |
| Наладчик | **UC-6.** Видит рецепт задания в карточке (веб и мобильная) только для чтения, с предупреждением о сумме. |
| Наблюдатель | Видит рецепты только для чтения. |
| Система | **UC-7.** Не даёт удалить материал, который есть в рецепте изделия или в копии задания (включая исходный материал заменённой строки). |

Вне объёма: альтернативы материалов, склад/остатки (не WMS), граммы на изделие (появятся с весом изделия в PZP-24),
журнал всех промежуточных замен (хранится только исходный и текущий материал), отдельный тип «добавка»
(добавки заводятся как пластики).

## Решения

1. Пропорция — **процент от массы изделия**. В 100 % входят **только пластики**; краситель в сумму не входит.
   Сумма пластиков ≠ 100 % — **предупреждение красным, не запрет**.
2. Рецепт изделия можно править; у задания своя копия, правка рецепта изделия задания не трогает.
3. Наладчику — только чтение.
4. Смена изделия в задании перезаписывает копию рецептом **нового** изделия; если копия правилась —
   подтверждение (проверяет **только фронт**, сервер перезаписывает молча).
5. «Изменён руками» **вычисляется**: хотя бы у одной строки копии `MaterialId != OriginalMaterialId`
   (замена туда и обратно правкой не считается).
6. Хранение — две таблицы строк (не `jsonb`, не версии рецепта). Тип ингредиента не хранится — это `Material.Type`
   (тип материала неизменен, замена только тем же типом).

## Модель данных

### `ProductRecipeIngredient : BaseEntity` (рецепт изделия)

| Поле | Тип | Примечание |
|---|---|---|
| `ProductId` | `Guid` | FK → `Product`, `Cascade` |
| `MaterialId` | `Guid` | FK → `Material`, `Restrict` |
| `Percent` | `decimal` `numeric(5,2)` | |
| `SortOrder` | `int` | порядок строк, из порядка в запросе |

Уникальный индекс `(ProductId, MaterialId)`. `Product.RecipeIngredients` — навигация. Пустой набор = «рецепта нет».
Cascade нужен для физического удаления изделия без ссылок (исключение мягкого удаления).

### `ShiftTaskRecipeIngredient : BaseEntity` (копия в задании)

| Поле | Тип | Примечание |
|---|---|---|
| `ShiftTaskId` | `Guid` | FK → `ShiftTask`, `Cascade` |
| `MaterialId` | `Guid` | текущий материал, FK → `Material`, `Restrict` |
| `OriginalMaterialId` | `Guid` | материал изделия на момент копирования, FK → `Material`, `Restrict` (аналитика, паспорт партии BL-27) |
| `Percent` | `numeric(5,2)` | не меняется после копирования |
| `SortOrder` | `int` | |

`ShiftTask.RecipeIngredients` — навигация. Строки не добавляются и не удаляются вручную, процент не правится —
только замена материала.

### Миграция `AddRecipes`

Две таблицы, индексы, FK. Существующим заданиям копия не заполняется (legacy-данных нет, рецептов ещё нет).

## Правила (Core)

### `RecipeRules` (`Core/Policies`, чистые функции)

`Validate(rows)` — `DomainException` (→ 400) с понятным текстом, если:
- строк больше **8**;
- процент ≤ 0, > 100 или больше двух знаков после запятой;
- **ингредиент повторяется** (один материал дважды в рецепте);
- рецепт **непустой и в нём нет ни одного пластика**;
- **новая** строка ссылается на архивный материал (строка, которая уже была в рецепте с этим материалом, остаётся допустимой).

Пустой рецепт допустим.

`PlasticSum(rows)` — сумма процентов строк с `MaterialType.Plastic`. `IsSumOk(rows)` — пустой рецепт **или**
`PlasticSum == 100`. Сумма не хранится, сохранения не блокирует.

### `Product`

`SetRecipe(rows, existingMaterialIds)` — валидация `RecipeRules` и замена набора строк целиком, `SortOrder` по порядку.

### `ShiftTask`

- `ApplyRecipe(productIngredients)` — перезаписывает копию: для каждой строки `MaterialId = OriginalMaterialId =`
  материал изделия, `Percent` и `SortOrder` — из изделия. Нет рецепта у изделия — копия пустая.
  Вызывается из `CreateTask` и из пути смены изделия (`SetProduct` при реальной смене; no-op при том же изделии — копия не трогается).
- `ReplaceIngredient(ingredientId, Material newMaterial)` — `DomainException`, если тип нового материала
  ≠ тип текущего или материал архивный. **Статус не проверяется** — разрешено в любом статусе, включая
  `Completed`/`Closed`. Выбор исходного материала возвращает строку к исходному.
- `RecipeEdited` (вычисляемое) — `RecipeIngredients.Any(i => i.MaterialId != i.OriginalMaterialId)`.

### `MaterialsController.UsedMaterialIdsAsync`

Объединение `ProductRecipeIngredient.MaterialId`, `ShiftTaskRecipeIngredient.MaterialId` и
`ShiftTaskRecipeIngredient.OriginalMaterialId` по запрошенному набору — включая архивные изделия и закрытые задания.
Даёт правильный `IsUsed` и 409 на `DELETE` используемого материала.

## API

### Изделие

- `ProductDto.Recipe: RecipeIngredientDto[]` (по `SortOrder`): `MaterialId`, `MaterialType`, `MaterialArticle`,
  `MaterialName`, `MaterialIsActive`, `Percent`. Отдаётся везде, где есть `ProductDto` (список и карточка типа).
- `PUT /api/producttypes/{id}/products/{productId}/recipe` — тело `{ "ingredients": [{ "materialId", "percent" }] }`,
  замена целиком, порядок массива = `SortOrder`, пустой массив очищает рецепт. Политика — как у правки изделия.
  Ответ — `ProductDto`. Ошибки: 400 (`RecipeRules`), 404 (нет типа/изделия/материала, изделие не этого типа).
  Сумма ≠ 100 % — не ошибка. Правка рецепта архивного изделия разрешена.

### Задание

- `TaskDto.RecipeIngredients: TaskRecipeIngredientDto[]`: `Id`, `MaterialId`, `MaterialType`, `MaterialArticle`,
  `MaterialName`, `OriginalMaterialId`, `OriginalMaterialArticle`, `OriginalMaterialName`, `Percent`.
  `TaskDto.RecipeEdited: bool` (вычисляется). Во всех ответах с `TaskDto` (список, `my`, карточка).
- `POST /api/tasks`, `PUT /api/tasks/{id}` — контракт без изменений; копию заполняет/перезаписывает сервер.
- `PUT /api/tasks/{id}/recipe/{ingredientId}` — тело `{ "materialId" }`, политика `ManagerOrAdmin`, любой статус.
  Ответ — `TaskDto`. Ошибки: 400 (другой тип, архивный материал), 404 (нет задания/строки/материала).
- Выбор материалов — существующий `GET /api/materials?type=…&isActive=true&search=…`.

## UI

### Утилита `src/utils/recipe.js`

`plasticSum(rows)`, `isRecipeSumOk(rows)` (пустой — ок), `formatRecipe(rows)` → «ПП-1 — 60 %; ПП-2 — 40 %; Краситель ААА — 2 %»
(порядок рецепта, разделитель «; »), `formatPercent(value)` — без лишних нулей. Используют все экраны ниже.

### Справочник изделий (`ProductTypeDictionary.vue`)

- Колонка «Рецепт» после «Наименования» — `formatRecipe`, текст переносится по ширине колонки; пусто — «—».
  Сумма пластиков ≠ 100 % — красный значок с подсказкой «Сумма пластиков: 98 % (должно быть 100 %)».
- Кнопка «Рецепт» в действиях строки изделия → диалог.

### Диалог `ProductRecipeDialog.vue` (новый)

- Заголовок — полный артикул и наименование.
- Таблица «Тип · Материал · Процент · ✕»: материал — `el-select` с поиском по активным материалам (тип в подписи,
  уже выбранные исключены); тип — из материала, только чтение; процент — `el-input-number`, шаг 0.01, 0.01..100.
- «Добавить ингредиент» — не больше 8 строк.
- Итог: «Пластики: 100 %» серым или «Пластики: 98 % — сумма пластиков отличается от 100 %» красным; сохранение не блокирует.
  Непустой рецепт без пластика — сообщение об ошибке, «Сохранить» недоступна (сервер проверяет то же).
- Строка с архивным материалом — метка «в архиве»; остаётся при сохранении, заменить можно только на активный.
- «Сохранить» → `PUT …/recipe`, перечитать тип; «Отмена» — без сохранения.

### Карточка задания (`TaskDetailModal.vue`, «Данные задания», под «Изделием»)

- Блок «Рецепт»: таблица «Тип · Материал · %»; заменённая строка — новый материал и серым «было: <артикул — наименование>».
- Итог по пластикам — как в диалоге. Пустая копия — «Рецепт не задан».
- Менеджер/админ: кнопка «Заменить» у строки в любом статусе → диалог с `el-select` активных материалов того же типа,
  исходный помечен «(исходный)»; ответ `TaskDto` обновляет карточку. Наладчик/наблюдатель — без кнопок.

### Форма задания (`TaskFormModal.vue`)

- Под выбором изделия — рецепт выбранного изделия, только чтение (`formatRecipe` + красный значок).
- Существующее задание с `RecipeEdited = true`: при выборе другого изделия в селекте — `ElMessageBox.confirm`
  «Рецепт в задании был изменён. При смене изделия изменения будут очищены. Хотите выбрать новое изделие?» (Да/Нет).
  «Нет» — вернуть прежнее изделие; «Да» — оставить, копию перезапишет сервер при сохранении. Новое задание — без диалога.

### Мобильная карточка (`MobileTaskDetailView.vue`)

Под «Изделием» — пункт «Рецепт»: строка на ингредиент «Материал — %», красный текст при сумме пластиков ≠ 100 %,
пусто — «—». Без кнопок.
