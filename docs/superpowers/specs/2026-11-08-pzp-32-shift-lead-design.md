# PZP-32 — Старший смены, план смен и назначение литейщиков на ТПА

- **Дата:** 2026-11-08
- **Задача:** PZP-32, блок А фидбека пилота ПЗП
- **Зависимости:** PZP-18 (график и выбор заданий смены), PZP-30 (роль `Operator`, необязательный логин, `CurrentShiftWindow`)
- **Статус:** дизайн согласован, ожидает плана реализации
- **ADR:** требуется ADR-0027 — новые сущности, контракты API, интервальная модель назначений и позиционная синхронизация плана с графиком

## Цель

Добавить роль старшего смены и отдельный мобильный контур работы, в котором он:

- видит ТПА и задания только в разрешённой смене;
- назначает и снимает литейщиков на любом ТПА, включая ТПА без задания;
- работает со своей ближайшей назначенной сменой и просматривает собственную историю.

Менеджер получает страницу «План смен», где назначает старших на конкретные даты и позиции графика. Все назначения литейщиков хранятся как интервалы с серверными метками времени и станут основой отчёта PZP-31.

## Акторы и сценарии (use cases)

| Актор | Сценарий | Результат |
|---|---|---|
| Manager / Admin | **UC-1.** Открывает «Планирование → План смен», выбирает произвольный диапазон дат. | Видит по одной строке на сутки и независимое число колонок в каждой строке. Прошедшие смены серые, текущая дата ярко выделена, будущие приглушены. В ячейке видны интервал и фамилия старшего. |
| Manager / Admin | **UC-2.** Открывает карточку будущей или ещё не начавшейся смены и назначает старшего. | Кандидаты — активные `ShiftLead` и `Manager`. Manager может назначить самого себя. Admin сам по себе кандидатом не является. На одну колонку назначается один человек; один человек может занимать несколько колонок даты. |
| Manager / Admin | **UC-3.** Меняет или очищает старшего до начала смены. | Переназначение сохраняет предварительные назначения литейщиков. Очистка запрещена, если в колонке есть назначения литейщиков. После начала смены старший не меняется; после окончания данные неизменяемы для всех ролей. |
| ShiftLead | **UC-4.** Входит в систему. | Попадает в отдельный мобильный UI, не связанный с UI наладчика. Видит ближайшую назначенную ему смену либо заглушку, если назначенных текущих и будущих смен нет. |
| ShiftLead | **UC-5.** Открывает ближайшую смену. | Видит компактный список всех активных ТПА, эффективное состояние, краткие сведения о заданиях и назначенных литейщиках. По нажатию открывает карточку ТПА с заданиями только для чтения. |
| ShiftLead / Manager / Admin | **UC-6.** Назначает литейщика на ТПА в ближайшей разрешённой смене. | Допускается ТПА без задания. Можно выбрать активного `Operator` без логина, уже назначенного на другой ТПА. Сервер фиксирует `AssignedAt`; одновременно допускается не более двух литейщиков на ТПА. |
| ShiftLead / Manager / Admin | **UC-7.** Снимает литейщика, затем при необходимости назначает его снова. | Снятие фиксирует `UnassignedAt`, запись не удаляется. Повторное назначение создаёт новый интервал. Освободившееся место можно занять другим литейщиком. |
| ShiftLead | **UC-8.** Открывает «История». | Видит только прошлые смены, где он был старшим. Внутри — ТПА, задания и интервалы литейщиков без элементов редактирования. Более поздние будущие назначения ему не показываются. |
| Manager / Admin | **UC-9.** Просматривает историю и будущие смены. | Видит все сохранённые смены. Назначать литейщиков может только в ближайшем вхождении каждой позиции графика; остальные смены доступны только для чтения. |
| Manager / Admin | **UC-10.** Изменяет число или границы интервалов в справочнике смен. | Сохранённые будущие дни синхронизируются по порядковым позициям. Лишние колонки удаляются вместе с будущими назначениями, новые добавляются пустыми, оставшиеся получают новые окна. Сохранённые текущие и прошлые дни не меняются. |
| Система | **UC-11.** Обрабатывает назначение до начала смены и снятие до или во время смены. | Фактическая работа начинается не раньше начала смены и заканчивается при снятии, но не позднее окончания смены. Назначение и снятие до начала образуют пустой фактический интервал, запись сохраняется. |
| Система | **UC-12.** Подготавливает данные для PZP-31. | Сохраняет все интервалы, окна смен и связи с ТПА. Распределение выработки и отчёт в PZP-32 не реализуются. |

## Основные решения

1. **`ShiftLead` — самостоятельная роль вне `Adjuster < Manager < Admin`.** В `AdjusterOrHigher` её не добавляем. Для новых API используется отдельная политика `ShiftLeadOrManagerOrAdmin`.
2. **Старший назначается на конкретную дату и позицию графика.** Постоянной привязки к смене справочника нет.
3. **Колонка плана — позиция интервала, а не стабильная сущность справочной смены.** Ссылка на `Shift.Id` в новых сущностях не нужна; существующее пересоздание записей справочника смен можно сохранить.
4. **В БД хранятся только дни хотя бы с одним старшим.** Остальные даты виртуально вычисляются из актуального графика.
5. **При первом назначении старшего сохраняется снимок всех колонок дня**, включая колонки без старшего. Поэтому у сохранённого дня прошлое не зависит от последующих правок справочника.
6. **Назначения литейщиков — интервальный журнал.** Физического удаления фактической истории нет. Удаляются только предварительные назначения в будущих колонках, удалённых при синхронизации графика.
7. **Один человек может быть старшим нескольких колонок одной даты.** Ограничение по числу колонок оставлено на усмотрение пользователя.
8. **Назначение литейщиков требует предварительного назначения старшего на колонку.** Manager/Admin не обходят это правило.
9. **Прошлые смены — только чтение для всех ролей.** Автоматического или ручного редактирования прошлых интервалов нет.

## Модель данных

### `ShiftPlanDay`

| Поле | Тип | Правило |
|---|---|---|
| `Id` | `Guid` | Первичный ключ |
| `ShiftDate` | `DateOnly` | Дата начала суток плана по заводскому времени; для ночной смены используется дата её начала |
| `Items` | коллекция | Полный снимок колонок графика на дату |

- `ShiftDate` уникальна.
- Запись существует, только пока хотя бы у одного `ShiftPlanItem` заполнен `ShiftLeadId`.
- При первом назначении старшего создаются день и все колонки актуального графика.
- После очистки последнего старшего день удаляется и снова становится виртуальным.

### `ShiftPlanItem`

| Поле | Тип | Правило |
|---|---|---|
| `Id` | `Guid` | Первичный ключ |
| `ShiftPlanDayId` | `Guid` | Родительский день |
| `Position` | `int` | Порядковый номер интервала, начиная с 1 |
| `StartAtUtc` / `EndAtUtc` | `DateTime` | Снимок окна смены, `Kind=Utc` |
| `TimeZoneId` | `string` | Заводской часовой пояс интервала |
| `ShiftLeadId` | `string?` | `User.Id` активного `ShiftLead` или `Manager`; `null` — старший не назначен |

Ограничения:

- уникальность `(ShiftPlanDayId, Position)`;
- один старший на колонку через единственное `ShiftLeadId`;
- **нет** уникальности `(ShiftPlanDayId, ShiftLeadId)`;
- FK к `User` и родительскому дню; FK к справочной `Shift` отсутствует;
- назначения литейщиков ссылаются на `ShiftPlanItem.Id`, а не на `Position` напрямую.

### `ShiftImmOperatorAssignment`

| Поле | Тип | Правило |
|---|---|---|
| `Id` | `Guid` | Первичный ключ |
| `ShiftPlanItemId` | `Guid` | Конкретная сохранённая смена |
| `ImmId` | `Guid` | ТПА |
| `OperatorId` | `string` | Пользователь с ролью `Operator` |
| `Slot` | `int` | Техническое место активного литейщика: только 1 или 2 |
| `AssignedAt` | `DateTime` | Серверное время назначения, UTC |
| `UnassignedAt` | `DateTime?` | Серверное время снятия; `null`, пока назначение активно |

Ограничения PostgreSQL:

- `Slot IN (1, 2)`;
- уникальность `(ShiftPlanItemId, ImmId, Slot)` **только для `UnassignedAt IS NULL`**;
- уникальность `(ShiftPlanItemId, ImmId, OperatorId)` **только для `UnassignedAt IS NULL`**;
- `UnassignedAt IS NULL OR UnassignedAt >= AssignedAt`;
- никакого уникального ограничения по `(ShiftPlanItemId, OperatorId)` между разными ТПА нет.

`Slot` не является рабочим местом в UI и не ограничивает число последовательных интервалов. Например, после снятия Иванова со слота 1 новый литейщик получает слот 1 новой записью, а запись Иванова остаётся в истории.

### Фактический интервал работы

Для отчёта PZP-31 используется пересечение назначения с окном смены:

```text
WorkStart = max(AssignedAt, ShiftPlanItem.StartAtUtc)
WorkEnd   = min(UnassignedAt ?? ShiftPlanItem.EndAtUtc, ShiftPlanItem.EndAtUtc)
```

- `WorkEnd < WorkStart` означает пустой фактический интервал.
- Неснятое назначение автоматически заканчивается вместе со сменой; фоновая задача для закрытия не нужна.
- Правило отнесения циклов к одному из двух одновременно работающих литейщиков определяется отдельно в PZP-31.

## Виртуальные дни и синхронизация с графиком

### Отображение произвольной даты

- Если `ShiftPlanDay` найден, план использует сохранённые `ShiftPlanItem`.
- Если записи нет, колонки вычисляются из актуального справочника смен, отсортированного по началу интервала; `Position` соответствует порядку.
- Виртуальные дни, включая текущие и прошлые без привязок, всегда отражают актуальный график: сохранённой истории у них нет.
- Сохранённые текущие и прошлые дни не пересчитываются.

### Материализация

При первом назначении старшего на виртуальную колонку в одной транзакции:

1. Создаётся `ShiftPlanDay`.
2. Создаются все `ShiftPlanItem` актуального графика с вычисленными UTC-окнами.
3. Выбранной позиции присваивается `ShiftLeadId`.

Клиент не передаёт границы окна.

### Изменение справочника смен

Сохранение справочника и синхронизация сохранённых дней выполняются в одной транзакции. Обрабатываются только `ShiftPlanDay.ShiftDate > текущая заводская дата`.

Для каждого сохранённого будущего дня:

1. Если новый график короче, удаляются все колонки с `Position > нового количества интервалов`. Их старшие и предварительные назначения литейщиков удаляются как ещё не наступивший план.
2. Если новый график длиннее, добавляются недостающие позиции с `ShiftLeadId = null`.
3. Все оставшиеся позиции получают `StartAtUtc`, `EndAtUtc` и `TimeZoneId` от интервала нового графика с той же позицией.
4. Существующие старшие и литейщики оставшихся колонок сохраняются.
5. Если в дне не осталось ни одного старшего, весь сохранённый день удаляется.

Сохранённые дни текущей заводской даты и раньше не изменяются, даже если сегодняшняя смена ещё не началась.

## Ближайшая смена и доступ

### Вычисление состояния смены

Смена — интервал времени, а не объект с фоновым автоматом состояний. Статус в БД не хранится и фоновая задача завершения не нужна. При каждом запросе сервер сравнивает `StartAtUtc` и `EndAtUtc` с серверным `now`:

```text
StartAtUtc <= now < EndAtUtc  → смена идёт
now < StartAtUtc              → смена будущая
now >= EndAtUtc               → смена историческая
```

В момент `EndAtUtc` при следующем обращении к серверу смена становится исторической, редактирование запрещается, а ближайшей становится следующая назначенная смена. Если следующей нет, остаётся только история. У неснятых назначений `UnassignedAt` остаётся `null`, но фактический интервал всё равно заканчивается в `EndAtUtc`.

Завершение смены не завершает производственное задание и не останавливает ТПА. Оно меняет только доступ к назначениям и отображение плана. Изменение справочника не сдвигает границы уже сохранённой текущей или прошлой смены.

### ShiftLead

Среди `ShiftPlanItem`, где `ShiftLeadId` равен текущему пользователю:

1. Выбирается текущая смена `StartAtUtc <= now < EndAtUtc`.
2. Если текущей нет, выбирается будущая с минимальным `StartAtUtc`.
3. Если ни текущей, ни будущей нет, доступна только история.

Только в этой ближайшей смене ShiftLead может назначать и снимать литейщиков. Если один человек назначен на несколько колонок даты, после окончания очередной смены ближайшей становится следующая.

Исторической считается смена с `EndAtUtc <= now`. ShiftLead видит только свои исторические смены. Другие будущие назначения сверх ближайшей ему не возвращаются.

### Manager / Admin

- Любой сохранённый и виртуальный план доступен для просмотра.
- Старшего можно назначить или переназначить на любую будущую дату, но только до `StartAtUtc` конкретной смены.
- Литейщиков можно менять в ближайшем вхождении каждой позиции графика: текущем либо earliest future с назначенным старшим.
- Более поздние будущие и прошлые назначения литейщиков доступны только для чтения.
- Manager, назначенный старшим на смену, сохраняет права Manager; запись ответственности не понижает и не повышает его роль.

### ТПА и задания

- В ближайшей смене возвращаются все активные ТПА, включая ТПА без задания.
- В истории дополнительно возвращаются архивные ТПА, если у них есть задания или назначения в этой смене.
- `Planned`/`Issued` отбираются по `PlannedStartAt` внутри окна смены.
- Остальные статусы отбираются по `TaskActivityWindow.OverlapsPeriod` с окном смены, включая завершённые в этой смене.
- Карточка задания и результаты доступны только для чтения и только после серверной проверки принадлежности к смене.
- Общие API заданий, произвольной истории ТПА и полного справочника персонала для ShiftLead не открываются.

## API

### План смен — только Manager/Admin

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/shift-plan?from=…&to=…` | Сохранённые и виртуальные дни, колонки, окна и старшие |
| GET | `/api/shift-plan/lead-candidates` | Активные `ShiftLead` и `Manager`: только `Id`, ФИО и табельный номер |
| PUT | `/api/shift-plan/days/{date}/items/{position}/lead` | Назначить, заменить или очистить старшего; тело содержит только `shiftLeadId` |

### Работа с литейщиками — ShiftLead/Manager/Admin

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/shift-staffing/nearest` | Ближайшая смена текущего ShiftLead |
| GET | `/api/shift-staffing/history` | Прошлые смены текущего ShiftLead |
| GET | `/api/shift-staffing/items/{itemId}` | Разрешённая смена: ТПА, задания и интервалы литейщиков |
| GET | `/api/shift-staffing/items/{itemId}/tasks/{taskId}` | Задание и результаты только для чтения после проверки принадлежности |
| GET | `/api/shift-staffing/operators` | Активные Operator: только `Id`, ФИО и табельный номер |
| POST | `/api/shift-staffing/items/{itemId}/operators` | Назначить литейщика; тело: `immId`, `operatorId` |
| POST | `/api/shift-staffing/assignments/{assignmentId}/unassign` | Снять литейщика; тело и клиентское время отсутствуют |

Manager/Admin открывают конкретный `itemId` из плана смен. `nearest` и `history` предназначены для персонального мобильного контура ShiftLead; широкие права Manager/Admin на план этим не ограничиваются.

Дата и окно смены, слот, `AssignedAt` и `UnassignedAt` от клиента не принимаются. Все операции используют серверные часы и серверное разрешение доступа.

## UI

### «Планирование → План смен»

- Новый пункт меню для Manager/Admin.
- Строка — одни сутки; у каждой строки собственное число колонок по её сохранённому или виртуальному графику.
- Общий заголовок «Дата | Смены и старшие»; каждая ячейка сама содержит подпись позиции и интервал.
- Прошедшие смены — серые, текущая дата — яркая рамка/подсветка, будущие — приглушённые.
- В ячейке отображается фамилия старшего или состояние «Не назначен».
- Нажатие открывает карточку колонки: окно, старший, действия, разрешённые по времени и роли.
- Разное число колонок не выравнивается в единую фиксированную сетку и не заменяется пустыми ячейками «Нет в графике».

### Мобильный UI ShiftLead

- Отдельные layout и route family; `MobileLayout` наладчика не используется.
- После login и при прямых переходах ShiftLead направляется на собственный домашний маршрут.
- Главный экран «Моя смена»: ближайшая смена и компактный список ТПА.
- UI устанавливает таймер на `EndAtUtc` и после его срабатывания повторно запрашивает ближайшую смену. Дополнительно данные обновляются каждые 60 секунд, чтобы отражать изменения других пользователей.
- После обновления показывается следующая смена либо завершившаяся открывается только для чтения. Устаревшие кнопки не являются защитой: сервер всё равно проверяет `now` при каждой операции.
- Нажатие на ТПА открывает карточку с эффективным состоянием, заданиями только для чтения и литейщиками.
- В карточке показаны `1/2` или `2/2`, имена, `AssignedAt`/`UnassignedAt`, кнопки «Снять» и «Назначить» только в разрешённой ближайшей смене.
- Для предварительного назначения отображается пояснение «Работа учитывается с начала смены».
- ТПА без задания показывает «Задание отсутствует», назначение остаётся доступным.
- Экран «История» содержит только собственные прошлые смены; внутри те же данные без кнопок изменения.
- Время назначения и снятия показывается в часовом поясе браузера; в БД остаётся UTC.
- Manager/Admin могут открыть тот же экран из выбранной смены плана; UI наладчика им для этого не нужен.

## Ошибки и согласованность

| Ситуация | Ответ |
|---|---|
| Нарушение доменного правила: третий литейщик, повторное активное назначение, смена началась, нет старшего, изменение прошлого | `400` с русским сообщением |
| Чужая или неближайшая смена ShiftLead; недопустимая роль | `403` |
| Смена, ТПА, задание или интервал не найдены | `404` |
| Параллельный запрос изменил состояние смены или состав литейщиков | `409`; UI сообщает и перезагружает данные |

- При назначении литейщика родительский `ShiftPlanItem` блокируется, выбирается свободный `Slot`, затем создаётся интервал. Частичные уникальные индексы остаются защитой от гонок.
- Снятие уже снятого назначения запрещено.
- Очистка старшего при наличии интервалов литейщиков запрещена; переназначение до начала смены разрешено и сохраняет интервалы.
- Назначение нового интервала на архивного Operator запрещено; существующие записи с архивным Operator остаются видимыми.
- Ошибка синхронизации графика откатывает и изменение справочника, и все изменения сохранённых будущих дней.
- Все `DateTime` в EF-запросах имеют `Kind=Utc`; заводская дата используется только для `DateOnly` и определения границы синхронизации.

## Тестирование

### Unit xUnit

- Выбор ближайшей смены: текущая, earliest future, несколько колонок одного человека, отсутствие назначений.
- Границы состояния: непосредственно до `StartAtUtc`, на начале, непосредственно до `EndAtUtc` и ровно на окончании; фоновое изменение записей не требуется.
- Фактический интервал: до смены, во время смены, после снятия, пустой интервал, автоматическое окончание в `EndAtUtc`.
- Синхронизация графика: меньше/больше/столько же интервалов, новые окна, удаление пустого дня, защита текущей и прошлых дат.
- Кандидаты старшего: `ShiftLead` и `Manager`, включая самого Manager; `Admin`, архивные и прочие роли исключены.
- Ночная смена и UTC-преобразования.

### Integration xUnit + Testcontainers

- Миграция и все check/уникальные ограничения.
- Материализация полного дня при первом старшем и удаление после очистки последнего.
- Назначение без задания, один/два/третий литейщик, повтор на том же ТПА, один Operator на нескольких ТПА.
- Снятие, повторное снятие, повторное назначение новым интервалом и параллельные запросы.
- Назначение и снятие до начала смены; запрет редактирования после начала и после окончания.
- Синхронизация будущих дней в одной транзакции и неизменность прошлого.
- Полная матрица ролей: ShiftLead/Manager/Admin допущены по правилам; Adjuster/Observer/Operator запрещены.
- ShiftLead не получает чужие, исторические до назначения и более поздние будущие смены; общие API заданий, истории и персонала остаются закрыты.
- Отбор Planned/Issued и активных/завершённых заданий по окну; активные и архивные ТПА в разрешённых режимах.
- Принадлежность задания и результатов к `itemId` проверяется сервером.

### Vitest

- Таблица с разным числом колонок, серым прошлым, выделенной текущей датой и приглушённым будущим.
- Карточка старшего: Manager может выбрать себя; запрет правки после начала; очистка с интервалами недоступна.
- Маршруты и редиректы ShiftLead не зависят от `isAdjuster`.
- Мобильный список ТПА → карточка → история.
- Таймер `EndAtUtc` запускает обновление; периодическое обновление выполняется каждые 60 секунд; после окончания элементы редактирования исчезают, а устаревшая операция обрабатывает серверный отказ.
- Назначение без задания, лимит два, снятие и повторное назначение, состояние загрузки и обновление после `409`.
- История не содержит элементов изменения.
- Новые экраны не вызывают общие API заданий, произвольной истории и полного справочника персонала.
