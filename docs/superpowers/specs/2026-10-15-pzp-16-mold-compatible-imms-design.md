# PZP-16 — Совместимые ТПА в карточке пресс-формы

- **Дата:** 2026-10-15
- **Задача:** PZP-16 (🔴 приоритет №3; предпосылка PZP-07 «Планирование на Гантте», функция 3
  «совместимость ТПА↔ПФ»). Закрывает требования РОСОМС «ПФ↔ТПА many-to-many» и «фильтр ПФ по ТПА».
- **Статус:** дизайн утверждён, готов к плану реализации
- **ADR:** ADR-0018 «Совместимость ПФ↔ТПА — ручной список» (пишется в рамках задачи)

## Проблема

Пресс-форма ставится не на любой ТПА: мешают габариты, усилие смыкания, ход и посадочные места.
Сейчас система об этом ничего не знает. При создании задания можно выбрать любую активную ПФ для
любого ТПА, и ошибка обнаруживается только в цеху. Планировщику на Гантте (PZP-07) нужно знать,
на какие ТПА можно переносить задание.

Исходная идея PZP-07 — физические параметры ПФ и ТПА и автоматический чекер — тяжёлая: нужно
заводить параметры в оба справочника и согласовывать правила. Ручной список совместимых ТПА
закрывает потребность сейчас. Автоматическую проверку можно добавить потом поверх него.

## Решения (зафиксированы при брейнсторминге 2026-10-15)

1. **Пустой список = «совместимость не указана» = подходит к любому ТПА.** После выката пилот
   работает как раньше, ограничение включается для каждой ПФ отдельно, когда у неё заполнен
   список.
   - Отвергнуто: пустой = «ни с одним». Заблокировало бы создание заданий на ПЗП до заполнения
     всех списков.
   - Отвергнуто: обязательный список с автозаполнением по истории. Лишняя работа и миграция
     данных ради строгости, которая на пилоте не нужна.
2. **Несовместимую пару нельзя сохранить.** В форме задания списки фильтруются, API отвечает 400.
   Если список ошибочен, его быстро исправляют: добавляют ТПА в карточку ПФ.
   - Отвергнуто: «разрешить с подтверждением» и «только предупреждать». Тогда список — лишь
     рекомендация, и планировщик не может на него опираться.
3. **Обратного вида в карточке ТПА нет.** Список редактируется только в карточке ПФ. На вопрос
   «что можно поставить на этот ТПА» отвечает фильтр в форме задания (YAGNI; данные позволяют
   добавить вид позже).
4. **Хранение — таблица связи `MoldCompatibleImms (MoldId, ImmId)`**, связь many-to-many в EF без
   класса-сущности.
   - Отвергнуто: явная сущность с `CreatedAt`/автором — аудит связи никому не нужен.
   - Отвергнуто: `jsonb Guid[]` в `Mold` — без целостности FK, фильтр через JSON-операторы.
5. **Архивные ТПА — как архивные типы изделий (ADR-0007).** Добавить архивный ТПА в список нельзя,
   но уже привязанный остаётся в списке при сохранении. Его можно удалить.
6. **Уже созданные задания не трогаем.** ТПА и ПФ задания неизменяемы после создания, поэтому
   совместимость проверяется только в `CreateTask`. Если после правки списка задание оказалось
   «несовместимым», его не помечаем и не блокируем. Коллизии плана покажет Гантт (PZP-07).

## Акторы и сценарии (use cases)

| Актор | Сценарий |
| --- | --- |
| Технолог / руководитель (Manager, Admin) | Открывает карточку ПФ, выбирает в «Совместимых ТПА» один или несколько ТПА, сохраняет. |
| Технолог / руководитель | Убирает ТПА из списка (ПФ больше не ставится на этот ТПА) или очищает список целиком (ПФ снова подходит к любому). |
| Технолог / руководитель | Отправляет ТПА в архив. Он остаётся в списках ПФ с пометкой «(архив)», в новые списки его добавить нельзя. |
| Планировщик (Manager, Admin) | Создаёт задание: выбирает ТПА и видит только совместимые ПФ (с этим ТПА в списке или с пустым списком). Или сначала выбирает ПФ и видит только совместимые ТПА. |
| Планировщик | Создаёт задание из заказа: ПФ фильтруются и по типу изделия заказа, и по совместимости с ТПА. |
| Наладчик (Adjuster) | Видит список совместимых ТПА в карточке ПФ (только чтение, как и остальные поля). |
| Внешний клиент API | `POST /api/tasks` с несовместимой парой получает 400. |

## Модель данных

```csharp
public class Mold : BaseEntity
{
    // ...
    // Совместимые ТПА (PZP-16, ADR-0018). Пусто — совместимость не указана, ПФ подходит к любому ТПА.
    public ICollection<Imm> CompatibleImms { get; set; } = new List<Imm>();
}
```

Конфигурация в `ApplicationDbContext`:

```csharp
builder.Entity<Mold>()
    .HasMany(m => m.CompatibleImms)
    .WithMany()
    .UsingEntity<Dictionary<string, object>>(
        "MoldCompatibleImms",
        r => r.HasOne<Imm>().WithMany().HasForeignKey("ImmId").OnDelete(DeleteBehavior.Restrict),
        l => l.HasOne<Mold>().WithMany().HasForeignKey("MoldId").OnDelete(DeleteBehavior.Cascade),
        j => { j.HasKey("MoldId", "ImmId"); j.HasIndex("ImmId"); });
```

У `Imm` навигации нет (обратного вида нет). Физического удаления нет, поэтому каскад от `Mold`
безопасен и нужен только для целостности. Миграция `AddMoldCompatibleImms` создаёт одну таблицу
без данных.

## Доменная политика

`Core/Policies/MoldImmCompatibility.cs` — чистая функция:

```csharp
public static class MoldImmCompatibility
{
    /// Пустой список — совместимость не указана, ПФ подходит к любому ТПА.
    public static bool IsCompatible(IReadOnlyCollection<Guid> compatibleImmIds, Guid immId)
        => compatibleImmIds.Count == 0 || compatibleImmIds.Contains(immId);
}
```

## API

**`MoldDto`** (список и карточка):

```json
"compatibleImms": [ { "id": "…", "name": "ТПА-3", "isActive": true } ]
```

Сортировка по `name`. В `GET /api/molds` подгружаются через `Include(m => m.CompatibleImms)`.

**`CreateMoldRequestDto` / `UpdateMoldRequestDto`:** `CompatibleImmIds: Guid[]?`.

- Create: `null` или `[]` → пустой список.
- Update: `null` → список не меняется (как и остальные nullable-поля запроса); массив → полная
  замена списка, `[]` — очистка.
- Дубликаты в массиве схлопываются.

**Валидация (Create/Update в `MoldsController`):**

- ID не найден среди `Imms` → 400 «Указан несуществующий ТПА.»
- ТПА архивный (`IsActive=false`) и не был в списке этой ПФ до запроса → 400 «Нельзя добавить
  архивный ТПА в список совместимых.» Для Create «до запроса» — пустой список, так что архивный
  ТПА отклоняется всегда.

**`POST /api/tasks` (`TasksController.CreateTask`):** после проверки ПФ загрузить ID её
совместимых ТПА. Если `!MoldImmCompatibility.IsCompatible(ids, request.ImmId)` → 400
«Пресс-форма не совместима с выбранным ТПА.»

Права не меняются: читают Admin/Manager/Adjuster, пишут Admin/Manager.

## UI

**Справочник ПФ ([MoldDictionary.vue](../../../Wintime-Control-Frontend/src/views/dictionary/MoldDictionary.vue))**

- Поле «Совместимые ТПА» в диалоге: `el-select multiple filterable clearable`. Опции — активные
  ТПА плюс уже связанные архивные этой ПФ с пометкой «(архив)». Архивные опции **не** `disabled`:
  в Element Plus тег отключённой опции нельзя снять. Повторное добавление снятого архивного ТПА в том
  же диалоге безопасно — сервер его примет, т.к. он был в списке до запроса. Подсказка под полем:
  «Пусто — подходит к любому ТПА».
- ТПА загружаются из `immApi` при открытии диалога.
- Колонка таблицы «ТПА»: имена через запятую (архивные с «(архив)») или серое «любой».

**Форма задания ([TaskFormModal.vue](../../../Wintime-Control-Frontend/src/views/tasks/TaskFormModal.vue))**

- `availableMolds`: к фильтру по типу изделия заказа добавляется условие — если ТПА выбран,
  остаются только ПФ, у которых `compatibleImms` пуст или содержит `form.immId`.
- Список ТПА: если ПФ выбрана и её `compatibleImms` не пуст, остаются только ТПА из него.
- Фильтры — вычисляемые свойства, поэтому ленивая загрузка списков по `@focus` остаётся как есть.
- В режиме редактирования (ТПА и ПФ заблокированы) фильтр совместимости **не** применяется: иначе
  выбранная ПФ «несовместимого» задания выпала бы из опций и селект показал бы сырой ID.
- Пустой список ПФ при выбранном ТПА: «Нет пресс-форм, совместимых с этим ТПА». Если вдобавок
  задан заказ — «Нет пресс-форм этого типа изделия, совместимых с этим ТПА».
- Описание ошибки 400 из API показывается как обычно (`ElMessage`).

## Тесты

**xUnit (unit):**

- `MoldImmCompatibility`: пустой список → true; ТПА в списке → true; ТПА не в списке → false.

**xUnit (integration):**

- `MoldsController`: создание со списком; Update `null` не трогает список; Update `[]` очищает;
  замена списка; несуществующий ТПА → 400; добавление архивного → 400; сохранение с ранее
  привязанным архивным → 200, связь остаётся; DTO содержит `compatibleImms` с `isActive`.
- `TasksController.CreateTask`: совместимая пара → 201; ПФ с пустым списком → 201; несовместимая
  → 400.

**Vitest:**

- `TaskFormModal`: при выбранном ТПА в списке ПФ остаются совместимые и с пустым списком; при
  выбранной ПФ со списком ТПА ограничены им; комбинация с заблокированным заказом; тексты
  пустого списка.
- `MoldDictionary`: поле отправляет `compatibleImmIds`; архивный связанный ТПА показан с «(архив)»;
  колонка таблицы — «любой» при пустом списке.

## Вне объёма

- Обратный вид в карточке ТПА.
- Физические параметры ПФ/ТПА и автоматическая проверка совместимости.
- Пометка уже созданных заданий, ставших несовместимыми.
- Подсказки на Гантте — в PZP-07.
- Мобильный UI наладчика (ПФ и ТПА там не выбираются).
