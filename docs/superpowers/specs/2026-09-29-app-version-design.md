# Версия приложения в UI — дизайн

**Дата:** 2026-09-29
**Статус:** утверждён

## Цель

Показывать в веб-интерфейсе номер и дату версии приложения, чтобы по экрану было видно,
какая сборка развёрнута (у себя, на VPS, у заказчика). Номер версии меняет разработчик
вручную при публикации.

## Акторы и сценарии (use cases)

**UC-1. Пользователь смотрит версию.**
Актор: любой авторизованный пользователь (десктоп).
Основной поток: открывает любую страницу с `DefaultLayout` → под надписью CONTROL видит
`v0.9.0 · 29.09.2026`; при наведении — подсказка `commit abc1234`.
Альтернативы: сборка без git (хэш недоступен) → подсказки нет, строка версии та же;
локальный `npm run dev` → вместо даты `dev` (`v0.9.0 · dev`).
Вне области: `MobileLayout`, `LoginView` — версию не показывают.
Тест: Vitest на `formatAppVersion` (формат даты, режим dev, отсутствие хэша).

**UC-2. Разработчик публикует новую версию.**
Актор: разработчик.
Основной поток: правит `VERSION` (например `0.9.0` → `0.9.1`), коммитит, запускает
`build.ps1` → фронт получает новую версию и дату сборки, сборки .NET — `<Version>` из
`VERSION`, Docker-образы помечены `:0.9.1` и `:latest`, оба запушены.
Альтернативы: забыл поднять `VERSION` → номер прежний, но дата сборки и хэш коммита новые,
сборку всё равно можно отличить; явно передан `-Tag` → он используется вместо значения из
`VERSION` (плюс `latest`).
Тест: ручная проверка вывода `build.ps1` / `docker images`.

**UC-3. Разработчик собирает пилотный пакет (ПЗП).**
Актор: разработчик.
Основной поток: `deploy/pzp/build-and-save.ps1` собирает как раньше (тег образа `pilot`
не меняется — на нём завязан compose у заказчика) и печатает собираемую версию.
Тест: ручная проверка вывода.

## Решения

| Вопрос | Решение |
|---|---|
| Формат номера | SemVer `MAJOR.MINOR.PATCH`, старт `0.9.0` |
| Источник правды | файл `VERSION` в корне репо, одна строка |
| Дата | дата сборки, проставляется автоматически |
| Где показывать | только `DefaultLayout` под CONTROL |
| Бэкенд | `Directory.Build.props` читает `VERSION` → `<Version>` |
| Эндпоинт `/api/version` | не делаем (фронт и бэк публикуются вместе) |
| Docker-теги (`build.ps1`) | `:<версия>` и `:latest` |
| ADR | не нужен — легко откатить |

## Компоненты

### 1. `VERSION` (корень репо)
Одна строка `0.9.0`, без префикса `v`, с завершающим переводом строки. Читающие стороны
делают `trim`.

### 2. Frontend — `Wintime-Control-Frontend/vite.config.js`
При загрузке конфига:
- читает `../VERSION` (trim);
- дата сборки — `new Date().toISOString()`;
- хэш — `git rev-parse --short HEAD` через `execSync`, при ошибке — пустая строка;
- через `define` вшивает `__APP_VERSION__`, `__BUILD_DATE__`, `__GIT_COMMIT__`
  (значения через `JSON.stringify`);
- в режиме `serve` (`npm run dev`) `__BUILD_DATE__` = `''` → UI показывает `dev`.

`defineConfig` переводится в функциональную форму `({ command }) => ({...})`, чтобы
различать `serve`/`build`.

Vitest использует отдельный `vitest.config.js`; в нём константы объявлены заглушками
(`'test'`, `''`, `''`), чтобы тесты, импортирующие `DefaultLayout`, не падали. Логику
покрывают тесты чистой `formatAppVersion` (значения передаются аргументами), а
обращение к `__APP_VERSION__` и др. живёт в отдельном модуле `buildInfo.js`.

### 3. Frontend — `src/utils/appVersion.js`
Чистая функция `formatAppVersion({ version, buildDate, commit })` →
`{ label, tooltip }`:
- `label`: `v${version} · ДД.ММ.ГГГГ` (дата в поясе браузера, см. правило «время на
  фронте — пояс браузера»); если `buildDate` пуст — `v${version} · dev`;
- `tooltip`: `commit ${commit}` или `''`.
Отдельный модуль `src/utils/buildInfo.js` экспортирует `appVersion` — результат функции
для вшитых констант; его импортирует `DefaultLayout.vue`.

### 4. Frontend — `src/layouts/DefaultLayout.vue`
Блок логотипа (`h-16`) становится столбиком: `CONTROL` + строка версии мелким серым
(`text-xs text-gray-400`), `title` = tooltip. Высота блока не меняется.

### 5. Backend — `Directory.Build.props` (корень репо)
```xml
<Project>
  <PropertyGroup>
    <Version>$([System.IO.File]::ReadAllText('$(MSBuildThisFileDirectory)VERSION').Trim())</Version>
  </PropertyGroup>
</Project>
```
Распространяется на все проекты решения (API, Core, Infrastructure, Shared, Emulator,
тесты, модуль Imm). Проверить, что ни один `.csproj` не задаёт свою `<Version>` и что
сборка тестов не ломается.

### 6. `build.ps1`
- `-Tag` по умолчанию = содержимое `VERSION` (trim);
- каждый образ собирается с двумя тегами: `:$Tag` и `:latest`; пушатся оба;
- в начале печатается `==> Version: $Tag`.

### 7. `deploy/pzp/build-and-save.ps1`
Тег `pilot` без изменений; добавить вывод `==> Version: <VERSION>` в начале.

### 8. `CLAUDE.md`
В раздел «Команды» — строка: перед публикацией поднять номер в `VERSION` (SemVer).

## Тестирование
- Vitest: `formatAppVersion` — нормальная сборка, `dev`, пустой хэш.
- `dotnet build` решения + прогон unit-тестов — `Directory.Build.props` ничего не ломает.
- `npm run build` → в бандле есть версия; визуальная проверка в `npm run dev`.
