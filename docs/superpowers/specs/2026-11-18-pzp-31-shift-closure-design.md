# PZP-31 — Сменный рапорт и закрытие смены

- **Дата:** 2026-11-18
- **Задача:** PZP-31, блок А фидбека пилота ПЗП
- **Зависимости:** PZP-18 («План работ на смену»), PZP-30 (`Operator`), PZP-32 (`ShiftLead`, план смен, интервалы литейщиков)
- **Статус:** дизайн согласован, ожидает плана реализации
- **ADR:** требуется новый ADR, уточняющий ADR-0027: фактические интервалы литейщиков, закрытие смены, снимок рапорта и распределение выпуска

## Цель

Заменить бумажный сменный рапорт электронным операционным документом. Старший смены назначает литейщиков на фактические интервалы работы, заполняет ручные показатели и закрывает смену. Система отдельно рассчитывает автоматические показатели по телеметрии, распределяет автоматический выпуск между литейщиками и сохраняет неизменяемый снимок закрытого рапорта.

PZP-31 не является аналитическим отчётом и не изменяет производственное задание, его общий выпуск или брак.

## Термины

- **Сменный рапорт** — операционный документ по одной позиции `ShiftPlanItem`.
- **Строка рапорта** — конкретное `ShiftTask` в конкретной смене, включая переходящее задание.
- **Автоматический выпуск** — сумма `ImmCycle.Cavities` по успешным закрытым циклам задания в учётном окне.
- **Ручные годные** — необязательное в обычном режиме число годных изделий, полученное старшим от литейщиков. Брак в это число не входит.
- **Ручной общий выпуск** — `Ручные годные + Ручной брак`.
- **Элементарный интервал** — часть смены между соседними границами назначений литейщиков.
- **Объединённый интервал** — соседние элементарные интервалы без разрыва с одинаковым списком литейщиков, объединённые до расчёта выпуска. `Slot` при сравнении состава не учитывается.
- **Интервал-сирота** — интервал с ненулевым автоматическим выпуском и без единого назначенного литейщика.
- **Ручной fallback** — обязательный ручной ввод полного цикла, годных и брака при любом `Offline` внутри окна выполнения задания в смене.
- **Досрочное закрытие** — закрытие с `ClosedAt < EndAtUtc`.

## Акторы и сценарии (use cases)

| Актор | Сценарий | Результат |
| --- | --- | --- |
| ShiftLead | **UC-1.** Во время смены назначает литейщиков и указывает фактические интервалы их работы, включая задним числом. | Система восстанавливает состав бригады в каждый момент и рассчитывает индивидуальный автоматический выпуск. |
| ShiftLead / Manager / Admin | **UC-2.** Открывает черновик сменного рапорта. | Видит актуальный состав заданий, плановые и автоматические показатели. Новые задания добавляются автоматически, отменённые не начавшиеся исчезают. |
| ShiftLead / Manager / Admin | **UC-3.** Исправляет интервал литейщика после окончания смены, но до её закрытия. | Черновик и распределение выпуска пересчитываются. Следующая смена остаётся доступной независимо от незакрытой предыдущей. |
| ShiftLead / Manager / Admin | **UC-4.** Печатает бланк до начала или во время смены. | Получает актуальные плановые и автоматические данные, пустые ручные поля и места для подписей. PDF помечен как незакрытый бланк и не становится неизменяемым документом. |
| ShiftLead / Manager / Admin | **UC-5.** Закрывает смену после её окончания. | Сервер проверяет данные и в одной транзакции фиксирует строки, показатели, составы и индивидуальные доли. |
| ShiftLead / Manager / Admin | **UC-6.** Закрывает смену досрочно. | После явного предупреждения сохраняется полный план смены и факт на `ClosedAt`. В документе фиксируется отметка о досрочном закрытии; позднейшие данные не попадают в него. |
| ShiftLead / Manager / Admin | **UC-7.** Открывает закрытый рапорт и формирует PDF. | Получает неизменяемый документ с ручными показателями, долями литейщиков, пустой колонкой «Принято на склад» и местами для подписей. |
| Manager / Admin | **UC-8.** Исправляет ручные фактические показатели закрытого рапорта. | Смена остаётся закрытой. Требуется причина; сохраняются автор, время и прежние/новые значения. Автоматические показатели, плановый снимок и литейщики не меняются. |
| ShiftLead | **UC-9.** Открывает «Моя смена», имея незакрытую предыдущую смену. | Видит отдельный блок «Требует закрытия» и одновременно может работать с ближайшей текущей/будущей сменой. |
| Manager / Admin | **UC-10.** Открывает «План смен». | Видит «Закрыта», «Не закрыта» и «Есть выпуск без литейщика», а также предупреждения об отсутствии старшего на текущую и ближайшую смену. |
| Manager / Admin | **UC-11.** Видит смену без назначенного старшего. | Закрытие такой смены не предусмотрено. Manager может назначить старшим себя, после чего смена материализуется и становится доступной для рапорта. |
| Система | **UC-12.** Обнаруживает `Offline` в окне выполнения задания. | Помечает строку как требующую ручного fallback. Ручной цикл, годные и брак становятся обязательными. |
| Система | **UC-13.** Обнаруживает выпуск в интервале без литейщика. | Показывает сироту на временной шкале и в плане смен, блокирует закрытие до назначения литейщика задним числом. |
| Система | **UC-14.** Закрывает смену без заданий. | Создаёт пустой закрытый рапорт, если у смены есть старший и выполнены условия доступа. |

## Жизненный цикл и права

### Черновик

- Существует только для материализованной `ShiftPlanItem` с назначенным `ShiftLeadId`.
- Создаётся в БД при первом ручном изменении; до этого черновик — динамическая read model.
- Плановые и автоматические колонки не копируются заранее: до закрытия они вычисляются из актуальных заданий, циклов и назначений.
- Состав строк пересчитывается при каждом чтении. Новые задания добавляются, отменённые не начавшиеся исчезают, начавшиеся остаются.
- Ручные значения сохраняются независимо от вычисляемого черновика.
- ShiftLead работает только с собственными сменами в `/shift-lead`; Manager/Admin — с любой сменой со старшим через «План работ на смену».

### Завершённая, но незакрытая смена

- После `EndAtUtc` смена попадает в `pending` и остаётся доступной для ручного ввода и исправления интервалов.
- Для ShiftLead она не заменяет nearest следующей смены: обе доступны через разные блоки UI.
- Состав литейщиков уже нельзя менять после закрытия, но до закрытия ретроактивные изменения разрешены и после `EndAtUtc`.

### Закрытие

- До `StartAtUtc` закрытие запрещено.
- Ограничения `now >= EndAtUtc` нет: досрочное закрытие разрешено с подтверждением.
- Фактическая граница расчёта:

```text
FactEnd = min(ClosedAt, EndAtUtc)
```

- В черновике до закрытия аналогичная граница — `min(now, EndAtUtc)`.
- При досрочном закрытии план остаётся рассчитанным на полное окно смены, а факт ограничен `ClosedAt`.
- Назначения, интервалы и все вычисляемые значения замораживаются в момент закрытия. Телеметрия, производство и ретро-привязки после закрытия снимок не изменяют.
- Повторное закрытие запрещено.

### Досрочное закрытие

- Клиент показывает предупреждение, что смена ещё идёт, автоматические показатели будут неполными и не обновятся.
- Клиент передаёт `confirmEarlyClose: true`; сервер проверяет признак независимо от UI.
- `ClosedEarly` вычисляется как `ClosedAt < EndAtUtc`, отдельное изменяемое поле не требуется.
- На экране и в PDF выводится: «Смена закрыта досрочно: фактическое время закрытия …, плановое окончание …».

### Исправления после закрытия

- Только Manager/Admin.
- Можно менять только ручной вес, ручной цикл, фактическую тарную единицу, количество мест, ручные годные и брак.
- Повторно открывать смену не требуется.
- Причина обязательна. Автор, время сохранения, причина и список прежних/новых значений сохраняются в аудите.
- Изменённые строки повторно проходят проверки по замороженным автоматическим данным и признаку fallback.
- Назначения, доли, план, нормативы и автоматические значения закрытого рапорта не редактируются.

## Состав строк и колонки рапорта

### Отбор заданий

Используется серверное `ShiftTaskWindow`, а не текущий frontend-selector PZP-18:

- `Planned`/`Issued` — по `PlannedStartAt` внутри `[ShiftStart, ShiftEnd)`;
- остальные статусы, включая `Completed`/`Closed`, — по `TaskActivityWindow.OverlapsPeriod` с окном смены.

Одно задание может появляться в рапортах нескольких смен. Значения каждой смены не являются итогами всего задания.

### Колонки

| Колонка | Источник и правило |
| --- | --- |
| ТПА | Наименование ТПА задания |
| Наименование | Наименование изделия задания |
| Остаток на начало смены | Невыпущенный остаток именно задания, не заказа |
| Сырьё | Пластики из `ShiftTaskRecipeIngredient` с процентами |
| Цвет/краситель | Красители из копии рецепта задания с процентами |
| Вес норма | `ShiftTask.PartWeightGrams` |
| Вес изделия | Ручной фактический вес одного изделия |
| Цикл норма | `ShiftTask.PlannedFullCycleSeconds` |
| Цикл автоматический | Средний `ImmCycle.DurationSeconds` в учётном окне |
| Цикл ручной | Ручной фактический полный цикл; обязателен только при fallback |
| Тарная единица | По умолчанию `ShiftTask.PackagingUnit`; старший может изменить фактическое значение только в рапорте |
| Количество мест | Необязательное неотрицательное десятичное число стандартных палет |
| Количество гнёзд | `ShiftTask.Cavities` |
| План | Нормативный план задания на смену |
| Выпуск автоматический | `Σ ImmCycle.Cavities` в учётном окне |
| Факт отлитых (годные) | Ручные годные без брака; необязательны, кроме fallback |
| Брак | Ручной брак; необязателен, кроме fallback |
| Принято на склад | Всегда пусто в процессах PZP-31 |
| Номер | Табельный номер литейщика |
| Литейщик | Литейщики, чьи интервалы пересекаются с окном выполнения задания |
| Автовыпуск литейщика | Индивидуальная доля автоматического выпуска; ручной выпуск не распределяется |
| Подпись | Пустое место для рукописной подписи |
| Расход | Плановый расход материала по формуле ниже |

Расхождение автоматического выпуска и `Ручные годные + Брак` не блокирует закрытие и не вызывает предупреждения. Расхождения нормативного и фактического веса/цикла также не блокируют его.

## Модель данных

### `ShiftClosure`

| Поле | Тип | Правило |
| --- | --- | --- |
| `Id` | `Guid` | Первичный ключ |
| `ShiftPlanItemId` | `Guid` | Уникально; одна смена — один рапорт |
| `State` | enum | `Draft` / `Closed` |
| `CreatedById` / `CreatedAt` | `string` / `DateTime` | Автор и серверное время первого сохранения |
| `ClosedById` / `ClosedAt` | `string?` / `DateTime?` | Заполняются при закрытии, UTC |
| `Entries` | коллекция | Строки рапорта |
| `Corrections` | коллекция | Аудит исправлений закрытого документа |

`ClosedEarly` вычисляется по `ClosedAt` и неизменному `ShiftPlanItem.EndAtUtc`.

### `ShiftClosureEntry`

Уникальность `(ShiftClosureId, ShiftTaskId)`.

В черновике запись создаётся для сохранения ручного ввода. При закрытии создаются записи всех актуальных строк, включая не редактировавшиеся; записи исчезнувших не начавшихся заданий в закрытый снимок не попадают.

Ручные поля:

- `ActualPartWeightGrams` — `decimal?`;
- `ManualFullCycleSeconds` — `int?`;
- `ActualPackagingUnit` — `int?`;
- `PackagingPlaces` — `decimal?`, два знака после запятой;
- `ManualGoodQuantity` — `int?`;
- `ManualDefectQuantity` — `int?`.

Снимок при закрытии включает:

- `ShiftTaskId`, `ImmId`, снимки наименований ТПА и изделия;
- снимки печатных представлений пластиков и красителей;
- остаток на начало смены;
- `NormPartWeightGrams`, `PlannedFullCycleSeconds`, `TaskPackagingUnit`, `Cavities`;
- `ShiftPlanQuantity`, `PlannedMaterialWeightGrams`;
- `AutomaticOutputQuantity`, `AutomaticAverageFullCycleSeconds`;
- `IsManualFallbackRequired`;
- финальные ручные значения.

FK сохраняет идентичность задания, ТПА и других сущностей, но печать и чтение закрытого документа используют снимки, а не актуальные справочники.

### `ShiftClosureOutputShare`

Одна строка на `ShiftClosureEntry` × объединённый интервал × литейщика:

- `ShiftClosureEntryId`;
- `IntervalStartUtc` / `IntervalEndUtc`;
- `OperatorId` и снимки ФИО/табельного номера;
- `SlotAtIntervalStart`;
- `Quantity` — целое `>= 0`.

Нулевые строки сохраняются для литейщиков, входящих в разрешённый состав строки, чтобы закрытый снимок сохранял и людей с нулевой долей. Строки строятся только для интервалов, пересекающих окно выполнения соответствующего задания внутри учётного окна смены.

Сумма по литейщику — его итог в задании. Детализация по интервалам объясняет происхождение итога. Ручные годные и брак сюда не копируются.

### `ShiftClosureCorrection`

- `ShiftClosureId`;
- `ChangedById`, `ChangedAt`;
- `Reason` — обязательная непустая строка;
- `ChangesJson` — список `taskId → field → oldValue → newValue` для одной пакетной правки.

JSON используется только для аудита. Рабочие значения остаются в типизированных колонках. Правка и аудит сохраняются в одной транзакции.

## Фактические интервалы литейщиков

### Изменение смысла PZP-32

`ShiftImmOperatorAssignment.AssignedAt` и `UnassignedAt` становятся фактическими границами работы, а не только временем нажатия кнопки. Дополнительно хранятся:

- автор и серверное время создания записи;
- автор и серверное время последней правки.

`UnassignedAt = null` означает работу до конца смены; background worker не нужен.

### Ввод и умолчания

- Начало при назначении по умолчанию — `ShiftStart`, даже если назначение создано позже.
- Конец при назначении по умолчанию — `ShiftEnd` (`UnassignedAt = null`).
- Обе границы можно указать произвольно внутри смены.
- При снятии конец по умолчанию — `min(max(now, WorkStart), ShiftEnd)`; его можно исправить. Поэтому отмена до начала работы создаёт пустой интервал, а снятие после окончания смены — интервал с концом `ShiftEnd`.
- Пустой интервал `WorkStart = WorkEnd` допускается только при назначении и снятии до начала работы, чтобы сохранить существующий сценарий отмены предварительного назначения. В расчётах он не участвует. Во всех остальных случаях `WorkStart < WorkEnd`.
- До начала смены назначение остаётся предварительным; фактическая работа всё равно ограничена окном смены.
- Редактирование разрешено ShiftLead собственной и Manager/Admin доступной смены до её закрытия, включая завершённую незакрытую.

### Ограничения PostgreSQL

- Границы находятся внутри окна смены; это проверяется сервисом под блокировкой, поскольку окно находится в родительской `ShiftPlanItem`.
- Одновременно на ТПА не более двух литейщиков.
- Один Operator не имеет пересекающихся интервалов на том же ТПА, но может одновременно работать на разных ТПА.
- `Slot` 1/2 выбирает сервер на весь сохраняемый интервал.
- Прежние partial unique indexes только для активных назначений заменяются временными exclusion constraints на полуоткрытых диапазонах: запрещены пересечения одного `Slot` и одного Operator внутри `(ShiftPlanItemId, ImmId)`.
- Если ни один `Slot` не свободен на всём запрошенном интервале из-за последовательных занятых участков, операция отклоняется `409`: пользователь должен скорректировать границы. Автоматического разбиения назначения между слотами нет.
- Изменения интервалов, плана и закрытия используют `ShiftScheduleLock`; выбор `Slot` и повторные проверки выполняются в транзакции.

## Расчёты

### Остаток задания на начало смены

```text
PreviousOutput = Σ Cavities успешных закрытых циклов задания с EndTime < ShiftStart
RemainingAtStart = max(0, PlanQuantity − PreviousOutput)
```

До закрытия остаток пересчитывается по актуальным циклам. При закрытии он фиксируется.

### План смены

Буфер выпуска не участвует.

1. Если `StartedAt` есть, используется фактическое окно выпуска `TaskActivityWindow.Release`.
2. Если выпуск ещё не начался, расчётное начало выпуска — `PlannedStartAt + PlannedSetupMinutes`.
3. Для не начавшегося выпуска расчётная длительность — `⌈PlanQuantity / Cavities⌉ × PlannedFullCycleSeconds`.
4. По пересечению окна выпуска с полным окном смены вычисляется нормативное количество по накопительной формуле, аналогичной `TaskPeriodPlan`: полные циклы × `Cavities`, с разностью накопленных значений на границах.
5. Результат ограничивается `RemainingAtStart`.
6. Для расчёта плана открытое фактическое окно условно продолжается до `ShiftEnd`, даже при досрочном закрытии: досрочность уменьшает только факт, не план.

Если эталон полного цикла или гнёздность не позволяют выполнить расчёт, план равен `0` по аналогии с существующей нормативной политикой.

### Плановый расход

```text
P = ShiftPlanQuantity
C = ShiftTask.Cavities
W = ShiftTask.PartWeightGrams
R = Product.RunnerWeightGrams

PlannedMaterialWeightKg = (P × W + ⌈P / C⌉ × R) / 1000
```

Литник учитывается один раз за смыкание, включая последний неполный цикл. В БД может храниться значение в граммах с преобразованием в кг только для отображения.

### Автоматические показатели

Выбираются только успешные закрытые циклы с `TaskId` текущей строки:

```text
EndTime >= ShiftStart
EndTime <  FactEnd

AutomaticOutputQuantity = Σ Cavities
AutomaticAverageFullCycleSeconds = AVG(DurationSeconds)
```

- Цикл относится к смене по `EndTime`, а не `StartTime`.
- Цикл, начавшийся до смены и завершившийся внутри неё, входит в неё.
- Цикл с `EndTime = ShiftEnd` относится к следующей смене.
- Открытые циклы исключены. После закрытия поздно закрывшиеся циклы снимок не изменяют.
- `PauseDurationMs` в средний полный цикл не добавляется.
- `IsSuccessful` — признак успешного машинного цикла, а не годности изделия.

### Построение и объединение интервалов

1. Назначения ТПА обрезаются учётным окном `[ShiftStart, FactEnd)`; пустые интервалы исключаются.
2. Все границы назначений образуют элементарные интервалы.
3. Соседние интервалы без временного разрыва и с одинаковым множеством `OperatorId` объединяются. `Slot` при сравнении не учитывается.
4. Границы заданий объединению не мешают: выпуск дополнительно группируется по `TaskId`.
5. Соседние интервалы без литейщиков объединяются по тому же правилу.

### Индивидуальное распределение

Для каждого объединённого интервала и каждого задания:

- один литейщик получает весь `Q`;
- два литейщика:
  - литейщик в `Slot = 1` **на начало объединённого интервала** получает `⌈Q / 2⌉`;
  - второй получает `⌊Q / 2⌋`;
- если слоты при неизменном составе позже поменялись, это не влияет на распределение за объединённый интервал;
- доли одного человека из разных интервалов суммируются;
- выпуск без литейщика — сирота.

Пример необходимости объединения до округления: два соседних интервала с одинаковой парой и выпуском `1 + 1` должны дать `2 → 1 + 1`, а не два независимых распределения `1 → 1 + 0` с итогом `2 + 0`.

Все операции используют полуоткрытые интервалы: цикл с `EndTime` ровно на границе относится к следующему интервалу.

## Валидация черновика и закрытия

Сохранение черновика проверяет типы и диапазоны заполненных полей, но не требует полноты. Полнота проверяется при закрытии и при исправлении закрытого документа.

### Общие условия закрытия

- `now >= StartAtUtc`;
- у смены назначен старший;
- действующий пользователь имеет доступ;
- нет ни одного интервала с ненулевым автоматическим выпуском без литейщика;
- при `ClosedAt < EndAtUtc` передано `confirmEarlyClose: true`;
- нет конкурентной правки или повторного закрытия.

Пустые интервалы с нулевым выпуском не блокируют закрытие. Смена без заданий закрывается с пустым рапортом.

### Строка без литейщиков

Если окно выполнения задания не пересекается ни с одним фактическим интервалом литейщика:

- ручные годные и брак автоматически фиксируются как `0`;
- остальные ручные поля необязательны;
- ручной fallback не требуется;
- ненулевой автоматический выпуск одновременно образует сироту и блокирует закрытие.

### Строка с литейщиками — обычный режим

Если в пересечении окна активности задания со сменой не было `Offline`:

- ручной цикл, годные и брак необязательны;
- автоматические показатели рассчитываются независимо от ручных.

### Строка с литейщиками — ручной fallback

Если хотя бы часть пересечения окна активности задания с `[ShiftStart, FactEnd)` имела сырой статус `Offline`:

- `ManualFullCycleSeconds` обязателен;
- `ManualGoodQuantity` обязателен;
- `ManualDefectQuantity` обязателен;
- наличие части автоматических циклов не отменяет требование.

`Offline` определяется по `ImmStatusHistory`, а не по отсутствию циклов. Онлайн-простой без циклов fallback не включает. Правило применяется только к строкам с литейщиками.

### Обязательность веса и тары

```text
Если AutomaticOutputQuantity > 0
   или ManualGoodQuantity + ManualDefectQuantity > 0:

   ActualPartWeightGrams > 0 — обязателен
   ActualPackagingUnit > 0 — обязателен
```

Пустые ручные годные/брак в этой проверке трактуются как отсутствие ручного выпуска, а не как явный ноль. Тарная единица подставляется из задания; если выпуск есть, а значение в задании отсутствует, старший обязан её ввести.

### Диапазоны

- ручные годные и брак — независимые целые `>= 0`; проверки `Брак <= Годные` нет;
- фактический вес — `> 0`, если заполнен;
- ручной цикл — целое `> 0`, если заполнен;
- фактическая тарная единица — целое `> 0`, если заполнено;
- количество мест — десятичное `>= 0` с двумя знаками, если заполнено; всегда необязательно.

## API

### `/api/shift-closures`

| Метод | Назначение |
| --- | --- |
| `GET /api/shift-closures/items/{itemId}` | Актуальный черновик либо закрытый снимок: строки, ручные поля, доли, fallback и досрочность |
| `GET /api/shift-closures/pending` | Завершённые незакрытые смены: ShiftLead — собственные, Manager/Admin — доступные |
| `PUT /api/shift-closures/items/{itemId}/draft` | Пакетное сохранение ручных полей; вычисляемые значения и состав строк клиент не передаёт |
| `POST /api/shift-closures/items/{itemId}/close` | Валидация и создание закрытого снимка в одной транзакции |
| `PATCH /api/shift-closures/{closureId}/corrections` | Пакетное исправление ручных полей с `reason`; только Manager/Admin |
| `GET /api/shift-closures/{closureId}/corrections` | История исправлений |
| `GET /api/shift-closures/items/{itemId}/blank-pdf` | Актуальный незакрытый бланк с пустыми ручными полями |
| `GET /api/shift-closures/{closureId}/pdf` | Неизменяемый PDF закрытого рапорта |

При досрочном закрытии без `confirmEarlyClose: true` возвращается `400 earlyCloseConfirmationRequired`. Клиентское время закрытия не принимается.

### Изменения `/api/shift-staffing`

| Метод | Назначение |
| --- | --- |
| `POST /items/{itemId}/operators` | Дополнительно принимает фактические `assignedAt`/`unassignedAt`; без них применяются умолчания |
| `POST /assignments/{assignmentId}/unassign` | Принимает необязательное фактическое `unassignedAt`; по умолчанию — `min(max(now, WorkStart), ShiftEnd)` |
| `PUT /assignments/{assignmentId}/interval` | Исправляет фактические начало и конец до закрытия смены |

Автор и время действия фиксируются сервером отдельно. Доступ к mutations больше не определяется только nearest: завершённая собственная незакрытая смена ShiftLead также доступна. После закрытия mutations запрещены.

### `/api/shift-plan`

Каждая материализованная позиция дополнительно возвращает:

- `closureStatus`: `Draft` / `Closed` / `NotClosed`;
- `hasOrphanOutput`: только ненулевой автоматический выпуск без литейщика;
- предупреждения об отсутствии старшего на текущей и ближайшей смене.

Виртуальная позиция без старшего закрытия не имеет.

### Коды ошибок

- `400` — невалидное значение, незаполненный fallback, выпуск-сирота, закрытие до начала, отсутствие early confirmation, изменение замороженных данных;
- `403` — чужая смена ShiftLead или недопустимая роль;
- `404` — смена, задание, назначение или рапорт не найдены;
- `409` — конкурентное изменение, временное ограничение назначения, serialization failure/deadlock.

Ошибки строк содержат `taskId` и коды полей.

## UI

### «План работ на смену» — ПК

Добавляется вкладка **«Сменный рапорт»** рядом с текущим назначением наладчиков. Используется только closure API; текущий frontend-selector заданий PZP-18 не переиспользуется, поскольку теряет `Completed`/`Closed`.

- Таблица повторяет колонки рапорта с группировкой веса, цикла и выпуска.
- Автоматические значения read-only, ручные редактируются в черновике.
- Строки fallback явно помечены.
- Ошибки показываются у конкретных строк и полей.
- Закрытый рапорт read-only; Manager/Admin получает «Исправить показатели» с причиной и историю исправлений.
- Доступны печать бланка до закрытия и закрытого рапорта после него.

### Мобильный `/shift-lead`

- На «Моя смена» — кнопка «Сменный рапорт» и отдельный блок «Требует закрытия».
- Строки представлены карточками заданий с теми же данными и проверками.
- Карточка ТПА содержит временную шкалу составов, сироты и редактирование интервалов.
- Доступны оба PDF-режима и история исправлений.
- Несохранённый ручной ввод не перезаписывается фоновым обновлением. Вычисляемые значения обновляются явно, после сохранения черновика или изменения интервалов.

### Временная шкала ТПА

Для каждого объединённого интервала показываются границы, список литейщиков и автоматический выпуск. Сирота с ненулевым выпуском выделяется. «Назначить» открывает форму с границами сироты. Пустой интервал с нулевым выпуском ошибкой не является.

Время на экранах — в поясе браузера, в БД — UTC.

### «План смен»

- «Закрыта» — есть закрытый `ShiftClosure`.
- «Не закрыта» — смена завершена, но не закрыта.
- «Есть выпуск без литейщика» — есть ненулевой сирота-выпуск.
- Отдельно — предупреждения об отсутствии старшего на текущую и ближайшую смену.

## Печать сменного рапорта

Используется QuestPDF, альбомная A4, повтор заголовков на каждой странице.

### Бланк

- Доступен до начала и во время смены, пока она не закрыта.
- Содержит актуальные плановые и автоматические показатели на момент формирования.
- Все поля ручного ввода пустые, даже если в электронном черновике уже есть сохранённые значения.
- Имеет отметку «Бланк — смена не закрыта» и серверное время формирования.
- Не сохраняется как неизменяемый документ.

### Закрытый рапорт

- Формируется только из закрытого снимка.
- Заголовок содержит дату/окно смены, старшего, автора и время закрытия.
- При досрочном закрытии содержит заметную отметку с `ClosedAt` и плановым `EndAtUtc`.
- Литейщики выводятся подстроками: табельный номер, ФИО, автоматическая доля и пустая подпись.
- Ручные годные и брак остаются общими по заданию.
- «Принято на склад» и «Подпись» не заполняются программой.
- Время в PDF — в `ShiftPlanItem.TimeZoneId`, на экране — в поясе браузера.

## Транзакции и конкурентность

Закрытие в одной транзакции под `ShiftScheduleLock`:

1. Повторно проверяет доступ и состояние.
2. Перечитывает задания, циклы и интервалы.
3. Выполняет расчёты и валидацию.
4. Сохраняет заголовок, строки и доли.
5. Переводит рапорт в `Closed`.

Параллельная правка интервалов или повторное закрытие преобразуется в `409`. Исправление закрытого рапорта и аудит атомарны. Нарушения exclusion constraints, serialization failure и deadlock обрабатываются как конфликт с перезагрузкой актуального состояния.

## Тестирование

### Unit xUnit

- Отбор строк: Planned/Issued, переходящие и Completed/Closed.
- Остаток и циклы на границе смены по `EndTime`.
- План: наладка, переходящее задание, неполная смена, ограничение остатком, полный план при досрочном закрытии.
- Расход: неполное последнее смыкание, нулевой план.
- Автоматический выпуск/средний цикл: открытые и неуспешные исключены, пауза не добавляется.
- Объединение интервалов по списку Operator без учёта `Slot`; разрывы не объединяются.
- `Slot 1` на начало объединённого интервала при последующей смене слотов.
- Чётный/нечётный выпуск, один/два/ноль литейщиков, суммирование долей, отсутствие потери/удвоения.
- Группировка по заданиям внутри одного интервала.
- Fallback: любой `Offline`, отсутствие `Offline`, онлайн-простой, строка без литейщиков.
- Обязательность веса/тары и необязательность ручного цикла/годных/брака в обычном режиме и количества мест всегда.
- Досрочное закрытие: `FactEnd`, признак и early confirmation.

### Integration xUnit + Testcontainers

- Миграция и временные exclusion constraints: два литейщика разрешены, третий и пересечения одного Operator запрещены, разные ТПА разрешены.
- Последовательные занятые слоты без единого свободного на всём интервале дают `409`.
- Пустой интервал только при отмене предварительного назначения.
- Динамический черновик и ручное сохранение.
- Закрытие и неизменность снимка после правок задания, поздней телеметрии и ретро-привязок.
- Закрытие не меняет `ShiftTask`.
- Сохранение всех долей и нулевых долей литейщиков.
- Сироты блокируют закрытие; ретроактивное назначение устраняет блокировку.
- Fallback и вся матрица обязательных полей.
- Досрочное закрытие, повторное закрытие и конкурентные операции.
- Исправления с причиной и аудитом; запрет для ShiftLead; атомарность отката.
- Pending, права собственных смен и смены без старшего.
- Оба PDF-режима и их доступ; закрытый PDF не меняется после последующих изменений данных.

- Таблица ПК и мобильные карточки, редактирование и ошибки полей.
- Временная шкала, объединённые интервалы и назначение на сироту.

- Изменение итогов `ShiftTask`, фоновое закрытие назначений или рапортов.
