# Отчёт «Производительность оборудования»: диаграмма на каждый ТПА — дизайн

**Дата:** 2026-10-03
**Статус:** утверждён

## Цель

Сейчас отчёт сводит все ТПА в одну поднёвную диаграмму. Она искажает картину: если часть ТПА
простаивала, а остальные работали на 100 %, суммарный столбец выглядит «средне» и не показывает
ни проблемных, ни здоровых машин. Переработка:

1. Вместо общей диаграммы — отдельная поднёвная диаграмма для **каждого** ТПА, строки
   расположены вертикально, у всех одна шкала 0–24 ч.
2. Фильтр по ТПА (множественный выбор) и фильтр архивных ТПА.
3. Категории столбца — **эффективный статус**, как на дашборде, плюс новая категория
   «Нет данных»; каждые сутки в сумме дают ровно свою длину (24 ч).

## Акторы и сценарии (use cases)

Акторы: Менеджер, Администратор (права эндпоинта не меняются: `Admin, Manager`).

**UC-1. Обзор парка за период.**
Основной поток: открывает отчёт → по умолчанию последние 7 суток, все неархивные ТПА →
видит карточки KPI, затем по строке на каждый ТПА (диаграмма по суткам + мини-сводка),
внизу итоговую таблицу. Цель — найти ТПА, которые мало работали, и понять причину
(наладка / простой / нет заданий / нет связи).

**UC-2. Сравнение выбранных ТПА.**
Основной поток: выбирает в мультиселекте несколько ТПА (например, участок) → «Сформировать».
Шкала 0–24 ч общая, строки сравниваются на глаз.
Альтернатива: снял выбор со всех ТПА → кнопка «Сформировать» неактивна, подсказка «Выберите ТПА».

**UC-3. История архивного ТПА.**
Предусловие: в БД есть хотя бы один ТПА с `IsActive = false`.
Основной поток: переключатель «Архивные ТПА» → «только» → список ТПА содержит только архивные,
все выбраны → «Сформировать» → видит, как работал выведенный из оборота ТПА.
Альтернатива: архивных ТПА нет → переключатель не отображается.

**UC-4. Выгрузка в Excel.**
Основной поток: «Excel» → файл с итоговой таблицей (7 статусов, циклы, средний цикл,
эффективность, строка «Итого») с теми же фильтрами, что на экране.

## Решения

### Категории столбца

| Категория | Ключ | Источник |
|---|---|---|
| Работа | `Production` | `ImmEffectiveStatus.Resolve` |
| Наладка | `Setup` | 〃 |
| Простой | `Downtime` | 〃 |
| Работа без задания | `Unplanned` | 〃 |
| Без задания | `NoTask` | 〃 |
| Нет связи | `Offline` | 〃 (явная запись `Offline` в `ImmStatusHistory`) |
| **Нет данных** (новая) | `NoData` | см. ниже |

**«Нет данных»** — время, о котором Control ничего не знает:
- промежутки, где в `ImmStatusHistory` нет ни одной записи (включая время до первой записи о ТПА);
- будущая часть сегодняшних суток (после «сейчас») и сутки целиком в будущем.

Отличие от «Нет связи»: «Нет связи» — известный факт (записан `Offline`); «Нет данных» —
записей нет вовсе. В «Нет данных» статус задания **не учитывается**: без телеметрии неизвестно,
работал ли ТПА, даже если задание было открыто.

`NoData` — категория только отчётного представления: в `ImmStatusHistory` не пишется, дашборд и
телеметрический таймлайн её не используют. ADR не заводится.

### Метрики

- **Известное время ТПА** = длина периода − «Нет связи» − «Нет данных».
- **Эффективность ТПА** = «Работа» / известное время × 100 %. Известное время = 0 → `null` («—»).
  «Работа без задания» и «Без задания» эффективность **снижают** — время не было под план.
- **Эффективность парка** = Σ «Работа» / Σ известного времени по всем ТПА отчёта (взвешенная,
  не среднее процентов). Σ = 0 → «—».
- **Проблемные ТПА** — две строки: эффективность < 70 % и < 50 % (вторая — подмножество первой).
  ТПА с «—» не учитываются.
- **Циклы / средний цикл** — только закрытые циклы (`EndTime != null`, `IsSuccessful`), начало
  в периоде — как сейчас.

### Подход к расчёту

Переиспользовать `EffectiveStatusTimeline.Build` в памяти с пакетной загрузкой входов
(три запроса на все выбранные ТПА). Отвергнуто:
- агрегация в SQL — дублирует матрицу `Resolve`, два источника правды разойдутся
  (дашборд ≠ отчёт);
- предрасчётная таблица суточных итогов — миграция и инвалидация при правках задним числом;
  не нужна при текущих объёмах (YAGNI).

## Бэкенд

### Core (чистая логика)

1. `EffectiveStatus.NoData = "NoData"` — новая константа.
2. `EffectiveStatusTimeline.Build(raw, tasks, downtimes, from, to, bool gapAsNoData = false)`:
   под-интервал без покрывающего сырого сегмента при `false` → `Offline` (как сейчас, дашборд и
   телеметрия не меняются), при `true` → `NoData` без вызова `Resolve`.
3. `DailyStatusBreakdown.Split(segments, days)` (`Infrastructure/Reports`, рядом с
   `FactoryCalendar` — `FactoryDay` там `internal`) — новая чистая функция: режет сегменты по
   суткам завода (`FactoryCalendar.Days`) и возвращает по каждым суткам словарь
   `статус → секунды`. Непокрытые сегментами части суток (в т.ч. хвост после «сейчас»)
   дополняются `NoData`, поэтому сумма по суткам = фактическая длина суток
   (24 ч; 23/25 ч в сутки перевода часов).

### Infrastructure

4. `IEffectiveStatusHistoryService` — сюда переезжает `ImmController.GatherEffectiveStatusInputsAsync`,
   становится пакетным:
   `GatherAsync(IReadOnlyCollection<Guid> immIds, DateTime fromUtc, DateTime toUtc, DateTime effectiveTo)`
   → `IReadOnlyDictionary<Guid, EffectiveStatusInputs>` (`raw`, `tasks`, `downtimes`).
   Три запроса с `ImmId IN (…)`; логика интервалов заданий и `ClampEnd` — без изменений.
   `ImmController` (оба эндпоинта: `effective-status-history` и телеметрический дашборд)
   вызывает его для одного ТПА.
5. `ReportService.GetEquipmentReportAsync(dateFrom, dateTo, immIds, archive)`:
   - `dateFrom > dateTo` → `ArgumentException` → контроллер отдаёт 400;
   - выборка ТПА: `archive` = `Exclude` (по умолчанию) → `IsActive`; `Include` → все;
     `Only` → `!IsActive`; затем, если `immIds` непуст, — пересечение с ним (id, не подходящие
     под режим архива, молча отбрасываются);
   - один `GatherAsync` → по каждому ТПА `Build(..., from = начало первых суток,
     to = min(конец периода, сейчас), gapAsNoData: true)` → `Split`;
   - циклы — один запрос на все ТПА, группировка по `ImmId`.

### Контракт API

`GET /api/reports/equipment?dateFrom=…&dateTo=…&immIds=…&immIds=…&archive=exclude|include|only`

`archive` — enum `ArchiveFilter { Exclude, Include, Only }`, биндится из строки без учёта
регистра; отсутствует → `Exclude`. В `ExportReportRequestDto` добавляется `Archive`.

```
EquipmentReportDto
  DateFrom, DateTo
  ImmData: List<EquipmentReportImmItemDto>

EquipmentReportImmItemDto
  ImmId, ImmName, IsActive
  Seconds: Dictionary<string, int>        // 7 ключей, всегда присутствуют (0, если нет)
  TotalCycles: int
  AvgCycleSeconds: decimal
  Efficiency: decimal?                    // null → «—»
  Days: List<EquipmentReportDayDto>

EquipmentReportDayDto
  Date: DateTime (Utc, дата суток завода)
  Seconds: Dictionary<string, int>        // 7 ключей
```

Удаляются: `EquipmentReportDto.DailyBreakdown`, `EquipmentReportDailyItemDto`, поля
`TotalWork/Setup/Downtime/OfflineSeconds` и `AvgEfficiency` в `EquipmentReportImmItemDto`.
Других потребителей нет (проверено поиском).

### Excel

Колонки: ТПА · Работа · Наладка · Простой · Работа без задания · Без задания · Нет связи ·
Нет данных (все в часах) · Циклы · Ср. цикл (с) · Эффективность %. Архивные ТПА — с пометкой
«(архив)» в имени. Строка «Итого»: суммы часов по статусам и циклов, ср. цикл — «—»,
эффективность — эффективность парка.

## Фронтенд

### Палитра

`constants/effectiveStatus.js`: новый экспорт `NO_DATA_STATUS` (`label: 'Нет данных'`,
`hex: '#e5e7eb'`) и `REPORT_STATUS = { ...EFFECTIVE_STATUS, NoData }` / `REPORT_STATUS_KEYS`.
`EFFECTIVE_STATUS` не меняется — его используют легенда `ImmDetailModal` и валидатор
`ImmStatusBadge`, туда «Нет данных» попадать не должно.
На диаграмме сегмент `NoData` дополнительно заштрихован (ECharts `decal`), чтобы не путать с
«Нет связи» (`#9ca3af`).

### Фильтры (ничего не запоминается)

- **Период** — `daterange`, по умолчанию последние 7 суток.
- **Архивные ТПА: нет / да / только** — `el-radio-group`. Список ТПА грузится один раз
  `GET /imm` (без `isActive` — все). Нет ни одного `isActive = false` → переключатель не
  рендерится. По умолчанию «нет».
- **ТПА** — `el-select multiple collapse-tags filterable`; варианты зависят от режима архива,
  архивные подписаны «(архив)». Смена режима → выбор сбрасывается на «все варианты режима».
  По умолчанию выбраны все. Пустой выбор → «Сформировать» неактивна.
- **Сформировать** → `immIds` (выбранные) + `archive`; «Excel» — те же параметры.
- Фильтры изменены после формирования → над отчётом предупреждение «Фильтры изменены — нажмите
  «Сформировать», чтобы обновить отчёт», сам отчёт приглушён; вернули фильтры как были — пометка
  снимается.
- `api/reports.js`: `getEquipment` с `paramsSerializer: { indexes: null }`
  (иначе axios шлёт `immIds[]=…`, ASP.NET не биндит).

### Карточки KPI

Всего ТПА · Эффективность парка · Проблемные ТПА (две строки: «< 70 %: N», «< 50 %: M») ·
Всего циклов. Считаются геттерами `stores/reports.js` (старые `overallEfficiency`,
`lowEfficiencyImms` заменяются).

### Список ТПА

- Над списком — одна общая легенда из 7 категорий (HTML по `EFFECTIVE_STATUS`); на диаграммах
  легенда скрыта.
- `components/reports/EquipmentImmRow.vue` — строка ТПА:
  - заголовок: имя, бейдж «Архив» при `!isActive`, эффективность справа;
  - слева `components/reports/EffectiveStatusDayChart.vue`: столбцы с накоплением по суткам,
    ось Y фиксирована `0–24` (шаг 6), высота ≈ 220 px; тултип — дата и часы по ненулевым
    статусам; `resize`-обработчик снимается в `onUnmounted`;
  - справа мини-сводка (≈ 240 px): часы по 7 статусам, циклы, средний цикл; на узком экране —
    под диаграммой.
- `v-loading` на весь список во время загрузки.

### Итоговая таблица

ТПА · 7 статусов (ч) · Циклы · Ср. цикл (с) · Эффективность. Строка «Итого» — как в Excel.

### Удаляется

Общая диаграмма «Загрузка ТПА по дням» и `components/reports/BarChart.vue` (используется
только в этом отчёте).

## Граничные случаи

- Сегодня: после «сейчас» — «Нет данных»; сутки целиком в будущем — столбец полностью
  «Нет данных».
- Сутки перевода часов: длина 23/25 ч; ось остаётся 0–24 (столбец 25 ч обрезается шкалой).
  Для поясов без перевода часов (РФ) не возникает.
- ТПА без записей за период: все столбцы «Нет данных», эффективность «—», в «проблемные»
  не попадает.
- Открытые циклы (`EndTime = null`) не входят в циклы и средний цикл.
- `immIds` с id, не подходящим под режим архива — отбрасывается.
- `dateFrom > dateTo` → 400.
- Ошибки сервера — как сейчас: 500 с сообщением, на фронте `ElMessage`.

## Тесты

**xUnit, Unit:**
- `EffectiveStatusTimeline.Build`: `gapAsNoData = true` → промежуток = `NoData`, даже при
  открытом задании; `false` → прежнее поведение (`Offline`).
- `DailyStatusBreakdown.Split`: сегмент через полночь делится между сутками; хвост после
  «сейчас» = `NoData`; сумма по суткам = длина суток; сутки 23/25 ч.

**xUnit, Integration:**
- `EffectiveStatusHistoryTests` — зелёные после переноса сбора входов в сервис.
- `GetEquipmentReportAsync`: поднёвная разбивка для двух ТПА с разной загрузкой; фильтр
  `immIds`; три режима `archive`; `Efficiency = null` без известного времени;
  `dateFrom > dateTo` → 400.

**Vitest:**
- `getEquipment` сериализует `immIds=a&immIds=b`.
- Геттеры стора: взвешенная эффективность парка, проблемные < 70 / < 50, исключение `null`.
- Переключатель архива скрыт без архивных ТПА.
- Число `EquipmentImmRow` = числу ТПА в ответе.

## Вне области

- Сохранение выбора фильтров между открытиями отчёта.
- Поднёвная разбивка в Excel.
- Изменение дашборда и телеметрического таймлайна (кроме переноса сбора входов в сервис).
- Ограничение длины периода (при длинных периодах столбцы просто становятся уже).
