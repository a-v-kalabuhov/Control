# Итоги выполнения задания — вкладка «Результаты выполнения»

- **Дата:** 2026-10-15
- **Источник:** вопрос ПЗП по отчёту «Производительность оборудования» (средний цикл за период
  бессмыслен при нескольких изделиях) → цикл и потери показываем по заданию.
- **Объём итерации:** только карточка задания. Отчёт-список по заданиям (BL-05) — следующим шагом
  на этом же расчёте.

## Акторы и сценарии (use cases)

| Актор | Сценарий |
|---|---|
| Мастер / менеджер | Открывает задание в работе и видит, идёт ли выпуск в темпе эталона и сколько уже потеряно на простоях и обрывах связи — не дожидаясь завершения. |
| Технолог (роль Manager) | После завершения сравнивает фактический цикл литья и полный цикл с эталонами задания; по расхождению решает, поправить ли эталон ПФ. |
| Мастер | Разбирает завершённое задание: план/выпуск/брак/перевыпуск и причину отклонения от плана. |
| Наладчик (Adjuster) | Видит итоги своего задания (те же права, что на чтение задания). |

Наблюдатель (Observer) карточку задания не открывает (`GET /api/tasks/{id}` ему не доступен) — вкладка
тоже нет.

## Определения

- **Окно выпуска** = `[StartedAt, CompletedAt ?? ClosedAt ?? now)` — `TaskActivityWindow.Release`.
  Простой бывает только во время выпуска, наладка в итоги не входит.
- Итоги **не хранятся**, считаются на лету при каждом запросе. Для задания в работе — на «сейчас»;
  после завершения окно закрыто, цифры стабильны.

## Показатели

### Выпуск (поля задания)

| Показатель | Формула |
|---|---|
| План | `PlanQuantity` (с учётом добавлений PZP-08; исходный план не историзирован) |
| Выпущено | `ActualQuantity` |
| Брак | `DefectQuantity` |
| Годных | `ActualQuantity − DefectQuantity` |
| Перевыпуск | `max(0, ActualQuantity − PlanQuantity)` |
| Причина отклонения от плана | `CloseReason`, если задание `Completed` и заполнено (одна причина на брак/перевыпуск/недовыпуск — отдельной причины брака нет) |

### Циклы

По закрытым успешным циклам задания: `ImmCycle.TaskId = id`, `IsSuccessful`, `EndTime != null`.

| Показатель | Факт | Эталон |
|---|---|---|
| Циклов | `COUNT` | — |
| Цикл литья | `AVG(InjectionDurationMs) / 1000` | `PlannedInjectionCycleSeconds` |
| Полный цикл | `AVG(DurationSeconds) + AVG(PauseDurationMs) / 1000` (как прогноз, ADR-0017; `null`-паузы в среднее не входят) | `PlannedFullCycleSeconds` |

Если закрытых циклов меньше `ReleaseForecast.MinClosedCycles` (3) — средние `null` («—»).
Если у циклов нет `InjectionDurationMs` — цикл литья `null`. Отклонение = (факт − эталон) / эталон,
считает фронт; нет эталона или факта — «—».

### Время выпуска

`EffectiveStatusHistoryService.GatherAsync` + `EffectiveStatusTimeline.Build` по окну выпуска
(`gapAsNoData: false` — дыра в сырой истории = «Нет связи», как на карточке ТПА).

| Показатель | Значение |
|---|---|
| Работа | Σ сегментов `Production`, с, и % от длины окна |
| Простои | Σ сегментов `Downtime`, с, %; **количество** = число `Event(Downtime)` на ТПА задания, пересекающих окно (авто и ручные) |
| Нет связи | Σ сегментов `Offline`, с, % (ADR-0019: без простоя «нет связи» не «работа») |

Прочие эффективные статусы внутри окна (теоретически `Setup` на краю) в UI не выводятся; сумма
процентов может отличаться от 100 % на округление. Цифры совпадают с карточкой ТПА и отчётом по
оборудованию — источник один.

## API

`GET /api/tasks/{id}/results` — роли `Admin, Manager, Adjuster` (как `GET /api/tasks/{id}`).
404 — задания нет.

```jsonc
// TaskResultsDto
{
  "releaseStarted": true,           // false → остальные блоки null, UI: «Выпуск ещё не начат»
  "releaseFrom": "…Z", "releaseTo": "…Z", "inProgress": true,   // окно; inProgress = окно открыто
  "output": {
    "planQuantity": 10000, "actualQuantity": 1134, "defectQuantity": 12,
    "goodQuantity": 1122, "overrunQuantity": 0, "deviationReason": null
  },
  "cycles": {
    "count": 567,
    "avgInjectionSeconds": 12.8, "plannedInjectionSeconds": 55,
    "avgFullCycleSeconds": 42.2, "plannedFullCycleSeconds": 60
  },
  "time": {
    "windowSeconds": 99120,
    "productionSeconds": 31260, "downtimeSeconds": 7500, "downtimeCount": 4, "offlineSeconds": 60360
  }
}
```

Проценты считает фронт от `windowSeconds`.

## Реализация

**Бэкенд**
- `ITaskResultsService` (Core/Interfaces) + `TaskResultsService` (Infrastructure/Services): одна
  точка расчёта, на ней же потом BL-05. Переиспользует `TaskActivityWindow.Release`,
  `IEffectiveStatusHistoryService`, `EffectiveStatusTimeline`, `ReleaseForecast.MinClosedCycles`.
- Эндпоинт в `TasksController`, DTO в `Core/DTOs/Tasks` (как `TaskDto`).
- Все `DateTime` в запросах — `Kind=Utc` (берутся из сущности и `UtcNow`).

**Фронт**
- `TaskDetailModal.vue`: `el-tabs` — «Данные задания» (текущее содержимое без изменений) и
  «Результаты выполнения» (новый компонент `TaskResultsTab.vue`).
- Данные вкладки грузятся при её открытии; пока `inProgress`, обновляются раз в минуту (таймер
  снимается при закрытии модалки/смене вкладки).
- Раскладка:

```
Окно выпуска: 14.10 16:09 — 15.10 19:41 (27 ч 32 мин)   [в работе]
ВЫПУСК    План · Выпущено · Брак · Годных · Перевыпуск; Причина отклонения от плана (если есть)
ЦИКЛЫ (N закрытых)          Факт     Эталон   Откл.
  Цикл литья                12,8 с   55 с     −77 %
  Полный цикл               42,2 с   60 с     −30 %
ВРЕМЯ ВЫПУСКА               Длит.        %
  ■ Работа / ■ Простои (N) / ■ Нет связи
  полоса долей (не хронология)
```

- Цвета статусов — `src/constants/effectiveStatus.js`. Отклонение: меньше эталона — зелёным,
  больше — красным.

## Тесты

- xUnit (Integration, `TaskResultsService` / эндпоинт): выпуск не начат; задание в работе (окно до
  now); завершённое; «Нет связи» внутри окна без простоя → `offlineSeconds`; простой, пересекающий
  границу окна, — в количестве и обрезан по окну; < 3 циклов → средние `null`; циклы без
  `InjectionDurationMs`; перевыпуск и годные; 404.
- Vitest (`TaskResultsTab`): «выпуск не начат»; проценты и отклонения; «—» без эталона/факта;
  причина показывается только при наличии.

## Не входит

- Отчёт-список по заданиям (BL-05), экспорт в Excel.
- Удаление «Ср. цикл» из отчёта «Производительность оборудования» — отдельная правка.
- Отдельная причина брака, справочник причин брака.
- Наладка «факт / норматив».
- Историзация исходного плана при «добавить к плану» (PZP-08).
