# ADR-0025. Гнёздовость: максимум ПФ, умолчание изделия, рабочая копия задания

- Status: Accepted
- Date: 2026-11-06
- Supersedes: [ADR-0001](0001-imm-cycle-cavities-snapshot.md)
- Related: [ADR-0023](0023-product-defaults-and-task-copy.md), [ADR-0024](0024-part-weight-product-task-snapshot.md), [ADR-0017](0017-release-forecast-mean-cycle-period.md)

## Контекст

Одна ПФ может иметь разные гнёзда для разных изделий: например, левый и правый винт.
Наладчик может заглушить часть гнёзд, поэтому фактический выпуск за цикл не всегда равен
физическому максимуму ПФ. В исходной номенклатуре ПЗП гнёздовость различается и между
изделиями одной ПФ, поэтому одного `Mold.Cavities` недостаточно.

При этом история должна оставаться стабильной: последующая правка справочника или задания
не должна пересчитывать уже записанные циклы. Нужны три разных значения вместо одного:
максимум оснастки, технологическое умолчание изделия и рабочее значение конкретного задания.

## Решение

1. **`Mold.Cavities` — максимальное количество гнёзд ПФ**, больше нуля. Это параметр оснастки,
   а не гарантированный выпуск каждого цикла.
2. **`Product.Cavities` — необязательное умолчание изделия**, больше нуля. `null` означает
   максимум выбранной ПФ. Если у типа несколько активных ПФ, умолчание не может превышать
   минимальный из их максимумов — тогда оно допустимо на любой из них. Создание, уменьшение
   и возврат ПФ из архива проверяются против умолчаний всех изделий типа; архивная ПФ ограничений
   не создаёт до возврата.
3. **`ShiftTask.Cavities` — обязательная рабочая копия**, больше нуля. При создании задания она
   равна `Product.Cavities ?? Mold.Cavities`. Менеджер/админ может выбрать любое значение от `1`
   до этого умолчания; повторное изменение после уменьшения тоже разрешено в тех же границах.
   Правка разрешена в любом статусе, поскольку гнёздо могут заглушить во время наладки или выпуска.
4. При реальной смене изделия в `Planned` рабочая копия сначала перезаписывается умолчанием нового
   изделия, затем применяется явно переданное значение. Последующая правка изделия или ПФ существующие
   задания не меняет. Неизменное значение старого задания остаётся допустимым, даже если новое
   справочное умолчание стало меньше: полная форма не должна падать при правке других полей.
5. **Новые и ретро-привязанные циклы получают `ImmCycle.Cavities = ShiftTask.Cavities`** на момент
   записи. Уже открытая строка при правке задания не переписывается. Выпуск и расход истории считаются
   по снапшотам циклов; изменение рабочей гнёздовости не пересчитывает `ActualQuantity`,
   `ActualMaterialWeightGrams` или старые циклы.
6. План задания, конфликты, нормативный план по периоду и прогноз окончания используют рабочую
   копию задания. Вес за смыкание в карточке ПФ — `PartWeightGrams × (Product.Cavities ?? Mold.Cavities)`.
7. Миграция добавляет оба поля и одноразово заполняет существующие задания из их ПФ. Существующие
   `ImmCycle.Cavities` не изменяются. Это заменяет источник снапшота из ADR-0001 и уточняет
   справочный расчёт веса за смыкание из ADR-0024.

## Отвергнутые альтернативы

- **Оставить только `Mold.Cavities`.** Не представляет разные изделия и заглушенные гнёзда;
  импорт номенклатуры вынужден произвольно выбирать одно значение.
- **Хранить гнёздовость только в каждом цикле.** Не даёт умолчания для новых заданий и планирования
  будущего выпуска; ретро-привязке тоже нужен источник значения.
- **Автоматически уменьшать существующие задания при правке справочника.** Молча меняет план и будущий
  выпуск, нарушает принцип независимой рабочей копии (ADR-0023/0024).
- **Ограничить правку статусами `Planned`/`Issued`.** Не позволяет отразить реальное заглушение гнёзда
  во время наладки или выпуска; исторические циклы и без того защищены снапшотами.
- **Молча ограничивать значение максимумом ПФ.** Скрывает ошибку ввода; вместо этого API отклоняет
  значение выше умолчания.

## Последствия

- В DTO изделия появилось nullable `cavities` с явным `clearCavities` при редактировании; в DTO задания —
  обязательное `cavities`, в запросах создания/обновления — необязательное переопределение.
- Изменение задания в середине цикла влияет только на следующие циклы. Менеджер отвечает за соответствие
  рабочего значения фактической конфигурации ТПА; телеметрия заглушенные гнёзда не распознаёт.
- Ограничение умолчания изделия минимумом активных ПФ типа консервативно: оно не позволяет назначить
  разные умолчания для разных ПФ одного типа. Если появится такая потребность, понадобится отдельная
  связь изделие ↔ ПФ, а не ослабление проверки молча.
- ADR-0001 сохраняется как история первого переноса гнёздовости в цикл; источником снапшота теперь
  является задание, а не ПФ.
