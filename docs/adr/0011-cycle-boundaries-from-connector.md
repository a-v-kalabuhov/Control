# ADR-0011: Границы цикла литья измеряет коннектор

- **Статус:** Accepted
- **Дата:** 2026-08-02

## Контекст

`CycleProcessingHandler` вычислял `ImmCycle.StartTime`/`EndTime`/`DurationSeconds` как
разность меток двух MQTT-сообщений — тех, между которыми изменился `cycleCounter`.
Метка сообщения — момент, когда коннектор сформировал очередной пакет опроса, а не
момент физического события на машине; между реальной границей цикла и ближайшим
опросом лежит до одного интервала опроса (500 мс по умолчанию) на каждой из двух
границ. Коннектор в это же время измеряет моменты точно (его автомат срабатывает по
фронтам сигналов формы), но раньше вычитал одно из другого и публиковал только
разность (`lastCycleDurationMs`), выбрасывая сами моменты.

`ADR-0010` вводит `injectionDuration`/`cyclePause` как способ получить длительности от
коннектора, но не решает вопрос границ: `StartTime`/`EndTime` оставались по меткам
сообщений, и в одной строке `ImmCycle` соседствовали миллисекундные длительности и
секундные границы без гарантии, что их сумма равна разности границ. На момент
принятия этого решения контракт `injectionDuration`/`cyclePause` не был реализован ни
на одном коннекторе — менять было нечего.

## Решение

Коннектор публикует два новых `ParameterType`: `cycleStart` (момент `mouldClosed↑`) и
`cycleEnd` (момент `mouldOpened↑`), оба — unix-миллисекунды, защёлкнуты между
событиями формы. `injectionDuration`/`cyclePause` из контракта убираются целиком —
заменяются, а не дополняются. Control выводит длительности и границы из этой пары
моментов: `EndTime = cycleEnd(N)`, `StartTime = cycleEnd(N−1)`,
`InjectionDurationMs = cycleEnd(N) − cycleStart(N)`,
`PauseDurationMs = cycleStart(N) − cycleEnd(N−1)`. Тем самым инвариант «сумма
длительностей равна разности границ» выполняется тождественно, а не приближённо.

Это отменяет разделы «Контракт с коннектором» (таблица `ParameterType`, строки 163-170)
и «Момент инкремента счётчика» (абзац «Чего перенос не даёт», строки 227-231) спеки
`2026-08-01-work-mode-and-two-level-cycle-design.md` — контракт длительностей
заменяется контрактом моментов.

## Альтернативы

- **Публиковать и моменты, и длительности одновременно** — отвергнуто: две версии
  одного числа способны разойтись, а правило «какая главная» ничем не обосновано;
  спека work-mode уже запрещала параллельную публикацию двух величин одного смысла.

## Последствия

- Новая зависимость: границы цикла и длительности теперь зависят от синхронизации
  часов ПК коннектора (NTP). Зависимость не новая по своей природе — на тех же часах
  уже строится `MqttTelemetryMessage.Timestamp` и `ImmStatusHistory` — но теперь она
  напрямую влияет на аналитику цикла, а не только на порядок строк. Требование
  зафиксировано в runbook пилотного деплоя, не в коде.
- Запасной путь не убран: коннекторы, которые Control не контролирует (OPC UA, Keba),
  и машины без выведенных сигналов формы продолжают работать по меткам сообщений,
  с `InjectionDurationMs`/`PauseDurationMs = null`. Признак способа измерения не
  вводится отдельным полем — `InjectionDurationMs != null` уже означает «границы
  измерены коннектором».
- Защита от протухшей, переставленной или бессмысленной защёлки — реализация несёт
  больше проверок, чем изначально описано здесь (добавлены по итогам код-ревью самой
  ветки): `cycleEnd(N) > cycleEnd(N−1)` (не протухла), `cycleEnd(N) ≥ cycleStart(N)`
  (не переставлена), `cycleStart(N) ≥ cycleEnd(N−1)` (пауза не отрицательная), обе
  сырые разности (`cycleEnd−cycleStart`, `cycleStart−prevEnd`) влезают в `int32`, и
  разрыв `cycleStart(N) − cycleEnd(N−1)` не превышает порог простоя ADR-0010
  (900 000 мс — см. Fix 1 финального ревью). При нарушении любой из первых пяти
  проверок цикл целиком пишется по запасному пути с предупреждением в лог (кроме
  ожидаемого двойного закрытия в SemiAuto — см. ниже, оно пишется в Debug); при
  нарушении только шестой (порог паузы) запасной путь не используется — впрыск
  остаётся измеренным сенсорами, отсекается только `PauseDurationMs` (см. следующий
  пункт).
- **SemiAuto закрывает каждый физический цикл дважды** (по `counterChanged`, затем по
  `modeChangedFromAuto` для того же ещё не сдвинувшегося латча `cycleEnd`) — это
  ожидаемый, рутинный паттерн, а не аномалия. Он тоже формально проваливает защиту
  «не протухла» (латч совпадает с предыдущим значением), но для него лог понижен до
  `Debug`, а не `Warning`, чтобы не шуметь на каждом цикле.
- **Известное ограничение запасного пути, принятое осознанно:** когда цикл закрывается
  по запасному пути (протухшая или переставленная защёлка `cycleStart`/`cycleEnd`),
  `CycleState.LastCycleEndMs` намеренно не сбрасывается — это сделано для того, чтобы
  одна плохая защёлка не убивала учёт пауз для всех последующих циклов. Плата за это:
  следующий цикл, чьи границы уже корректно выведены из сенсоров, возьмёт своим
  `StartTime` то самое, ещё не сброшенное `LastCycleEndMs` с точки до сбоя — его
  интервал протянется назад через весь запасной цикл, и промежутки двух соседних строк
  `ImmCycle` пересекутся; любая агрегация длительностей/простоев по этой паре задвоит
  общий отрезок. Решение принято осознанно при реализации: сбои по запасному пути
  ожидаются редкими (протухшая/переставленная защёлка, а не просто отсутствие
  сенсоров), а сброс защёлки на каждом запасном пути вместо этого терял бы реальное
  измерение паузы при каждом рестарте после сбоя. Вернуться к вопросу, если задвоение
  на уровне агрегации станет заметно в продовой аналитике.
- Реализация на стороне коннектора (`Wintime.Connector.UsrModbus`) — отдельная задача
  вне этого репозитория; включение контракта на пилоте должно ждать её готовности.
- **Первая строка после рестарта/долгого разрыва — короче соседних, и это осознанно.**
  Первый цикл после любого рестарта (`LastCycleEndMs` ещё не известен) и, после Fix 1
  финального ревью, любой цикл после разрыва, превышающего порог паузы ADR-0010
  (900 000 мс), пишется с `PauseDurationMs = null` и `StartTime = cycleStart(N)` —
  а не `cycleEnd(N−1)`, как обычно. `DurationSeconds` для этой одной строки измеряет
  только впрыск, а не полное окно «пауза + впрыск», которое АДР иначе гарантирует.
  Альтернатива — не писать строку вовсе — отвергнута: потерять реальный, штатно
  измеренный цикл ради формальной однородности длительностей хуже, чем один короткий
  ряд. Это ожидаемое поведение, не баг: если в будущем `ImmCycle.DurationSeconds`
  окажется у части строк заметно короче соседних без видимой причины — смотри сюда,
  а не ищи регрессию.
