# ADR-0028. Рабочая гнёздность задания ограничена максимумом ПФ

- Status: Accepted
- Date: 2026-11-18
- Supersedes: [ADR-0025](0025-cavities-mold-product-task.md)
- Related: [ADR-0001](0001-imm-cycle-cavities-snapshot.md), [ADR-0023](0023-product-defaults-and-task-copy.md), [ADR-0024](0024-part-weight-product-task-snapshot.md)

## Контекст

ADR-0025 разделил максимум ПФ, технологическое умолчание изделия и рабочую гнёздность задания,
но ограничил рабочее значение умолчанием `Product.Cavities ?? Mold.Cavities`. Это не позволяло
менеджеру выбрать значение между умолчанием изделия и физическим максимумом выбранной ПФ, хотя
такая настройка допустима технологически.

Нужно сохранить автоматическое заполнение из изделия, но проверять введённое значение по оснастке.
История циклов и независимость снапшотов задания от последующих правок справочников должны остаться
прежними.

## Решение

1. **`Mold.Cavities` — максимальная гнёздность ПФ**, больше нуля, а не гарантированный выпуск цикла.
2. **`Product.Cavities` — необязательное технологическое умолчание изделия**, больше нуля.
   `null` означает максимум выбранной ПФ. Ограничения умолчаний изделий минимумом активных ПФ типа
   сохраняются.
3. **`ShiftTask.Cavities` — обязательная рабочая копия**, по умолчанию
   `Product.Cavities ?? Mold.Cavities`. Менеджер/админ может выбрать в любом статусе любое целое
   значение от `1` до `Mold.Cavities`, включая значение выше умолчания изделия.
4. При реальной смене изделия в `Planned` рабочая копия сначала перезаписывается умолчанием нового
   изделия, затем применяется явно переданное значение. Создание и обновление задания проверяют
   значение по текущему максимуму выбранной ПФ. Неизменное старое значение может быть выше нового
   умолчания изделия, но значение выше максимума ПФ отклоняется и при неизменной правке.
5. **Новые и ретро-привязанные циклы получают `ImmCycle.Cavities = ShiftTask.Cavities`** на момент
   записи. Уже открытая строка при правке задания не переписывается. Выпуск и расход истории считаются
   только по снапшотам циклов; правка рабочей гнёздности не пересчитывает старые циклы,
   `ActualQuantity` или `ActualMaterialWeightGrams`. Для старых записей с нулём остаётся fallback
   на `Mold.Cavities`.
6. План задания, конфликты, нормативный план по периоду и прогноз окончания используют рабочую копию
   задания. Вес за смыкание в карточке ПФ — `PartWeightGrams × (Product.Cavities ?? Mold.Cavities)`.
7. Frontend разделяет умолчание изделия и максимум ПФ. Backend применяет ту же проверку при создании
   и обновлении, поэтому ограничение нельзя обойти прямым вызовом API.

## Отвергнутые альтернативы

- **Оставить ограничение умолчанием изделия.** Запрещает допустимые значения до физического максимума ПФ.
- **Молча обрезать значение по максимуму.** Скрывает ошибку ввода; API и форма должны отклонить её.
- **Разрешить старым заданиям оставаться выше максимума ПФ.** Противоречит единой проверке при сохранении
  и оставляет недопустимую рабочую конфигурацию без исправления.
- **Ограничить правку статусами `Planned`/`Issued`.** Не позволяет отразить реальную конфигурацию гнёзд
  во время наладки или выпуска; исторические циклы защищены снапшотами.

## Последствия

- Схема БД и формат DTO не меняются; меняются только автозаполнение и границы проверки.
- Уменьшение максимума ПФ не переписывает существующие задания автоматически, но при следующем
  сохранении значение выше нового максимума потребуется исправить.
- Изменение задания в середине цикла влияет только на следующие циклы. Телеметрия заглушенные гнёзда
  не распознаёт; менеджер отвечает за соответствие рабочего значения фактической конфигурации ТПА.
