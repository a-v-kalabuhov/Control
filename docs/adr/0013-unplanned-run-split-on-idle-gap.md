# ADR-0013: Эпизод «работы без задания» разрывается простоем дольше порога

- **Статус:** Accepted
- **Дата:** 2026-09-30
- **Дополняет:** ADR-0008 (заменяет отложенный пункт «sweep-воркер B2»)

## Контекст

По ADR-0008 эпизод `UnplannedRun` закрывался только в `StartTask`. Если ТПА работал без задания,
останавливался на несколько часов и снова работал без задания, обе сессии сливались в один
эпизод длиной почти в сутки (найдено на смоук-тесте с эмулятором USR-Modbus). Журнал показывал
неверную картину, а счётчик на карточке ТПА (PZP-06) суммировал циклы обеих сессий.

## Решение

Граница эпизода определяется **лениво, на приходе сироты-цикла** в `UnplannedRunHandler`:
если у ТПА есть открытый эпизод и между концом его последнего сироты-цикла и началом текущего
цикла прошло больше `DowntimeSettings.IdleThresholdSeconds` (по умолчанию 900 с, ADR-0010),
старый эпизод закрывается (`ClosedAt` = конец его последнего цикла), открывается новый.
Закрытие в `StartTask` сохраняется без изменений.

Порог — тот же, что у детекта простоя: пауза, которую Control считает простоем, логично
считать и границей эпизода.

## Альтернативы

- **Sweep-воркер по таймауту (B2)** — отклонён пока: отдельный фоновый сервис ради «живого»
  закрытия, которое никому не нужно — конец эпизода в журнале и так деривится по последнему циклу.
- **Отдельный порог для эпизодов** — отклонён: вторая настройка с тем же смыслом «сколько
  тишины считать перерывом», риск рассинхрона с детектом простоя.

## Последствия

- Две сессии без задания, разделённые простоем, — два эпизода; назначать задание можно каждому.
- Схема БД не меняется; +1 запрос `MAX(EndTime)` по индексу на каждый сирота-цикл.
- Пока новый цикл не пришёл, эпизод после остановки ТПА остаётся открытым (`ClosedAt = null`);
  его окно по-прежнему `[StartTime, COALESCE(ClosedAt, now())]`, но циклов в хвосте нет.
- Уже слипшиеся эпизоды в существующих БД не разделяются задним числом.
