# ADR-0023. Технологические умолчания изделия и их копия в задании

- Status: Accepted
- Date: 2026-11-03
- Related: [ADR-0020](0020-product-types-and-products.md), [ADR-0002](0002-task-state-machine-in-entity.md)

## Контекст

Изделию нужны технологические умолчания: рецепт (состав сырья в процентах от массы),
позже — вес изделия и прочие параметры (PZP-24/PZP-23). Задание же должно лить по тем
значениям, которые действовали на момент его создания: правка справочника не должна
задним числом менять уже выданные задания и испортить аналитику и паспорт партии (BL-27).

Отдельная потребность производства: нужного пластика может не быть на складе, и менеджер
должен заменить ингредиент в конкретном задании, не трогая справочник изделия.

## Решение

1. **Изделие хранит умолчания, задание — их копию.** `Product.SetRecipe` — эталон;
   `ShiftTask.ApplyRecipe` копирует его при создании задания и при реальной смене изделия.
   Правка рецепта изделия существующие задания не меняет.
2. **Строки, а не `jsonb` и не версии рецепта.** Две таблицы: `ProductRecipeIngredients`
   и `ShiftTaskRecipeIngredients`. Строки дают внешние ключи на `Material` (материал нельзя
   удалить из-под рецепта), дешёвую выборку «где используется материал» и обычные миграции.
   Версии рецепта отвергнуты: истории рецепта сейчас никто не спрашивает, а копия в задании
   уже фиксирует факт.
3. **Тип ингредиента не хранится** — это `Material.Type`. Тип материала неизменен, замена
   разрешена только тем же типом, поэтому денормализация не нужна.
4. **«Рецепт правился вручную» вычисляется**, а не хранится: строка копии помнит
   `OriginalMaterialId`, признак — `MaterialId != OriginalMaterialId`. Замена туда и обратно
   правкой не считается — это верное отражение, а не компромисс.
5. **Проверка при смене изделия — только на фронте.** Сервер перезаписывает копию молча:
   правило «подтверди потерю правки» — про UX, а не про целостность данных.
6. **Сумма пластиков ≠ 100 % — предупреждение.** Технолог видит красный итог, но сохранить
   может: рецепт может быть неполным на момент ввода. В 100 % входят только пластики.

## Последствия

- Замена материала разрешена в **любом** статусе задания, включая `Completed`/`Closed`:
  исправление ошибки наладки не должно требовать правки справочника.
- Материал, на который ссылается рецепт или `OriginalMaterialId`, физически не удаляется —
  только в архив (`409` на `DELETE /api/materials/{id}`).
- Каждое новое умолчание изделия (вес, упаковка, допуски) добавляется по этому же принципу:
  колонка/строка у `Product` + копия в задании при создании.

## Отвергнутые альтернативы

- **Один `jsonb`-столбец рецепта.** Нет FK на материалы, нельзя ответить «где используется
  материал» без разбора всех документов, миграции состава — через код.
- **Версии рецепта с датой действия.** Дороже и не нужно: копия в задании уже несёт факт.
- **Хранить признак «правился» флагом.** Рассинхронизируется при возврате исходного материала.
