# Тип изделия и изделие (`ProductType`, `Product`)

> Номенклатура: тип изделия («Крышка 48мм») и его изделия — товарные позиции с артикулами
> («Чёрная», «Белая»). ПФ выпускает тип, заказ и задание ссылаются на конкретное изделие.

## Что это

Двухуровневый каталог. **Тип изделия** — то, что отливает пресс-форма; у типа может быть несколько
**изделий** (цветов, исполнений), у каждого свой артикул в 1С/CRM. Одному типу может соответствовать
несколько ПФ (изношенную заменяют новой). Справочник ведут технолог/руководитель; планировщик выбирает
изделие в заказе и задании; наладчик видит его в карточке задания (какой материал и краситель
загружать).

## Ключевые поля

| Поле | Смысл и правила |
|---|---|
| `ProductType.Article` | Артикул типа. Уникален, заглавными (сервер: Trim + верхний регистр), не совпадает ни с одним `Product.FullArticle` |
| `ProductType.Name` | Наименование типа |
| `ProductType.IsActive` | Архивный флаг. Архивный тип нельзя привязать к ПФ и выбрать в новом заказе/задании; ссылки сохраняются |
| `Product.Article` | Часть артикула (`BLK`, `0`). Буквы и точки разрешены |
| `Product.FullArticle` | `Article типа + "." + часть`, например `A123.BLK`. Хранится, unique-индекс. Пересчитывается при правке артикула типа или части |
| `Product.Name` | Наименование изделия, обязательно. У изделия по умолчанию — «По умолчанию» |
| `Product.IsActive` | Архивный флаг изделия |

## Инварианты (нарушение = баг)

- Полный артикул уникален и не совпадает с артикулом типа (и наоборот) — строка из 1С должна
  указывать на одну сущность. → [ADR-0020](../adr/0020-product-types-and-products.md)
- У типа всегда ≥1 изделия (при создании — изделие `0` «По умолчанию»); у активного типа ≥1 активного:
  нельзя архивировать последнее активное изделие и вернуть из архива тип без активных изделий.
- Правка артикула типа пересчитывает `FullArticle` изделий в одной транзакции; при конфликте — откат.
- Физически удаляется только изделие без заказов и заданий, не последнее у типа (исключение из
  мягкого удаления).
- Изделие задания принадлежит типу ПФ задания; меняется только в `Planned` без заказа.
- Привязка задания к заказу — только при совпадении изделия задания и заказа.
- Тип ПФ нельзя сменить, если по ПФ есть задания (кроме `null → value`).
