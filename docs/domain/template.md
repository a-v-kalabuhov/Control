# Шаблон оборудования (`Template`)

> Описание модели ТПА: какие датчики приходят по MQTT, какого они типа и как их называть в интерфейсе.
> ТПА ссылается на шаблон (`Imm.TemplateId`); несколько ТПА одной модели используют один шаблон.

## Что это

Шаблон задаёт администратор (раздел «Шаблоны» — правка JSON или импорт файла). По шаблону Control
проверяет и сохраняет телеметрию (тип значения, допустимые значения, порог изменения), а интерфейс
показывает датчики: фильтр датчиков и графики на странице «Мониторинг». Для коннекторов шаблон ещё и
сообщает, откуда читать сигналы (поля коннектора, напр. `opc_path`) — см. скил `connector-integration`.

## Код

- Сущность: `Wintime.Control.Core.Entities.Template`; датчик — `SensorTemplate` (разобранный `JsonConfig`).
- Разбор: `Infrastructure/Cache/TemplateCache.Parse`; проверка телеметрии — `ValidateTelemetryDataHandler`.
- Связанные: `Imm` ([`imm.md`](imm.md)).

## Ключевые поля

| Поле | Смысл и правила |
|---|---|
| `Name`, `Manufacturer`, `Model`, `Version`, `Author` | Описание шаблона в справочнике |
| `ConnectorType` | Тип коннектора (`usr-modbus`, `opc-ua`, …); `null` — ТПА шлёт MQTT сам |
| `IsActive` | Архивный флаг (как у ТПА/ПФ) |
| `JsonConfig` | Конфигурация датчиков — JSON, структура ниже |

### `JsonConfig`

```json
{
  "device_timeout_seconds": 30,
  "sensors": [
    { "name": "Смыкание формы",          "field": "MoldClosed",        "type": "boolean" },
    { "name": "Положение шнека, мВ",     "field": "InjectionPosition", "type": "float", "threshold": 0.5 }
  ]
}
```

| Поле | Обязательное | Смысл и правила |
|---|---|---|
| `device_timeout_seconds` | нет (по умолчанию 30) | Через сколько секунд без сообщений ТПА считается «Нет связи» |
| `sensors` | **да** | Массив датчиков |

Датчик (`sensors[]`):

| Поле | Обязательное | Смысл и правила |
|---|---|---|
| `field` | **да** | Имя сигнала в MQTT-сообщении (ключ в `sensors` телеметрии). Уникально в шаблоне. Имя `cycleCounter` зарезервировано |
| `name` | **да** | Читаемое название для людей: подпись в фильтре датчиков и заголовок графика на «Мониторинге». Если не задано — показывается `field` |
| `type` | **да** | `float`, `int`, `boolean` или `string`; значение другого типа отклоняется. Если не задано — `float` |
| `threshold` | нет (0) | Порог изменения для COV-фильтра (ADR-0005): изменение меньше порога не сохраняется. 0 — сохранять каждое значение |
| `allowed_values` | нет | Список допустимых строковых значений; другое значение отклоняется |
| `required` | нет (`false`) | `true` — без этого датчика всё сообщение отклоняется |
| поля коннектора | — | Напр. `opc_path`; Control их игнорирует, читает коннектор |

## Инварианты (нарушение = баг)

- Обязательные поля датчика — `field`, `type`, `name`. **Сейчас при сохранении и импорте шаблона они не
  проверяются** (отсутствующие становятся пустой строкой / `float`) — проверка в беклоге (BL-44). Пока её нет,
  интерфейс подставляет `field` вместо пустого `name`.
- `field` уникален в шаблоне — по нему сопоставляются значения телеметрии и датчики.
